# Headless 配置生成

公开仓只生成 Mihomo 配置，不部署服务。发布、拉取、systemd 和客户端选择恢复由私有仓 `sshopt-private` 负责。节点清单设计仍是提案；当前使用 `subscriptions`、`roles`、`customProxies`、`customRuleGroups` 和 `options`。

主脚本重构方案见[统一配置参考](./统一配置参考.md)：全部节点、用途、链路和分流功能在 `完全覆写.js` 实现，独立生成器准备参数并调用同一个 `main(config)`。该文档中的新增 `USER_OPTIONS.nodes/roles/defaults` 尚未实现；本页描述当前可执行格式。

## 使用

需要支持内建 `fetch` 的 Node.js。在仓库根目录执行 `npm ci`，复制 `hosts/*.example.js` 为自己的主机文件，并准备本地 `secrets.env`。真实主机文件、秘密和 `out/` 均被 Git 忽略。

```bash
node scripts/render-config.js --host myhost
node scripts/render-config.js --all
node scripts/render-config.js --host myhost --offline
```

默认执行 `mihomo -t`；`--mihomo` 指定内核，`--mihomo-dir` 指定含 GeoSite/GeoIP 缓存的隔离校验目录。`--no-test` 只用于排查，不代表配置已经通过内核验证。渲染器不会重载正在运行的客户端。

## 输入与凭证

- `subscriptions` 接受远程订阅、本地路径或 `file://` URL；Windows 盘符、UNC 路径及编码后的文件名按系统路径解析。
- `roles.home`、`roles.front`、`roles.cnReturn` 和 `customProxies` 可写 `{ secret: "KEY" }`、`{ uri: "secret:KEY" }` 或完整节点。协议字段包括 TLS 会保留。
- `customProxies` 的 `dedicated` 默认 `false`；`roles.cnReturn` 未指定新旧字段时默认 `true`，显式 `dedicated: false` 允许回国节点进入通用候选。兼容旧 `scope: "ordinary" / "dedicated"`，新旧字段冲突或布尔值写成字符串均由主脚本报错，管理字段不会写入最终节点。
- 普通 `customProxies` 默认跟随 `🔗 前置`，无需节点级开关；默认 DIRECT 不加前置，选代理才增加一跳。专用节点需要同时作为前置时，在 `options.front.include` 填其名称，不必再填一份 `roles.front`。主脚本统一检查候选与隔离；专用节点不进入普通出口池，且不能剥离已有显式上游。
- `optional: true` 且秘密缺失时，已命名的 `roles.cnReturn` / `customProxies` 节点连同 `front.include` 中对它的引用一起跳过。只处理明确因凭证缺失跳过的节点，拼错名称仍报错；普通名称引用不能当成 optional 使用。
- 旧 `useFrontProxy` 和 `allowAsFront` 仍兼容，含义与[配置教程](./配置教程.md#方式三配置前置代理)一致。新配置无需填写；`roles.front` 仍保持旧的默认选中行为，运行中的缓存选择也不会强制重置。
- URI 之外的字段也会递归解析 `secret:KEY`。必需凭证缺失则失败，不覆盖旧输出；出口明确写 `optional: true` 时缺少凭证才跳过。
- `customRuleGroups` 的内嵌凭证是必需的；不能静默删除密码后继续输出。
- `roles.relay.prefer` 只可选择原家宽跳板候选及其叶节点，不能添加家宽自身、专用回国出口或前置副本。所有后处理结束后再次校验引用和循环。
- `runtime` 控制端口、控制器和 TUN；`runtime.extra` 也必须通过最终引用校验。

## 缓存与离线

缓存身份包含主机名、订阅名、完整 URL 和 User-Agent。只有同一身份可以在下载失败或 `--offline` 时使用缓存；旧版仅按名称生成的缓存不再作为回退来源。首次升级需成功拉取一次。

离线时仍需要配置原订阅 URL 或对应秘密，以确定准确的缓存身份。更换订阅账户、URL、主机名或 User-Agent 后，必须先拉取新来源，不能借用旧缓存。日志不打印订阅 URL 或秘密值。

## 输出与权限

`out/<host>.yaml` 包含真实节点凭证，不应公开提交。POSIX 系统使用目录 0700、配置文件 0600；Windows 使用 NTFS ACL，`chmod` 不能替代 ACL 隔离，应检查 secrets、hosts、out 所在目录只允许所需账户访问。

`selections` 写入 YAML 头部 `cocp-selections` 注释，仅供部署工具读取；它不会改变配置里的候选顺序，也不会在渲染时调用控制器。实际首次默认项由策略组候选顺序决定，运行中的历史选择还可能保存在客户端缓存中。
