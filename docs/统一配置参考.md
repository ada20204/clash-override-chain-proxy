## 功能统一放在完全覆写.js

两种运行方式最终执行同一个 `main(config)`：

```text
Clash Party 提供订阅配置 + 主脚本 USER_OPTIONS / 可选凭证注入
                         |
                         v
              完全覆写.js 的 main(config)
                         ^
                         |
独立生成器读取订阅、解析凭证、注入同一套 USER_OPTIONS
```

`完全覆写.js` 使用 ES5，负责全部节点归一化、用途绑定、组成员、前置副本、家宽链路、业务规则、DNS/Sniffer/QUIC、默认选择和引用校验。它可以由 Clash Party 调用，也可以在独立 JavaScript 运行环境中调用；功能实现不能依赖 Node.js 的文件、网络或环境变量 API。

独立生成器负责下载/读取订阅、读取主机参数与凭证、调用主脚本，以及设置监听端口等运行参数、输出 YAML 和执行内核校验。它不另写一套角色、地区、业务规则或链路算法。凭证注入脚本也只提供数据，主脚本负责解释数据并生成行为。

当前 `scripts/render-config.js` 的 `runOverride()` 已经载入主脚本、覆盖 `USER_OPTIONS` 并调用 `main(config)`。现有 `applyRelayPrefs()` 仍在生成器内修改家宽跳板候选；重构时应把这部分排序与过滤移入主脚本，由两种运行方式共用，旧 `roles.relay` 只做参数适配。

主脚本内部按以下顺序组织；这些是同一文件内的处理步骤，不增加新的运行入口：

1. 在 `main(config)` 中读取有效用户参数，归一化旧 `_homeProxy`、`_frontProxy`、`_customProxies` 输入。
2. 合并订阅和自定义节点，校验名称、稳定 ID、用途与固定上级。
3. 创建普通出口、国内出口、前置、家宽及其链式路径，并生成各业务组。
4. 按统一出口生成规则、DNS、Sniffer、QUIC 和 location 默认项。
5. 校验所有节点/组引用、环路和协议能力，返回完整配置。

参数读取与依赖这些参数的派生计算必须发生在调用时，以适应生成器在脚本载入后注入参数。每次调用使用独立的有效配置，避免一次覆写的临时状态污染下一次。

## 配置参考文件怎么提供

主要参考是主脚本顶部的用户参数区和本文。凭证分离、主机文件和独立生成器按运行需要选用。

| 文件 | 用途 | 使用者需要修改的内容 |
|---|---|---|
| `src/完全覆写.js` 顶部 `USER_OPTIONS` | 主参数入口，下面直接实现全部覆写功能 | 本机位置、自定义节点、用途绑定和初始选择 |
| `src/出口IP凭证_样本.js` | 唯一的本地配置样本，放在主脚本之前 | 家宽、自定义/前置节点和业务规则数据；由主脚本统一处理 |
| `hosts/cn-desktop.example.js` | 国内主机的命令行生成样本 | 订阅、统一配置、端口和 TUN |
| `hosts/overseas-cloud.example.js` | 海外 VPS 的命令行生成样本 | 同上；国内节点可同时作为前置候选 |
| `secrets.env.example` | 命令行生成器的凭证变量说明 | 仅保留空值或占位内容，真实值放本地 `secrets.env` |
| 本文 | 两种入口共用的字段说明和场景推演 | 更新接口时同步维护 |

新增用户参数及样本更新是待实现的交付内容；现在已有的 `hosts/*.example.js` 仍使用当前接口。不再以新增独立的 `节点配置_样本.js` 为实现前提，也不新增 `_nodeConfig` / `nodeConfig` 包装入口。

## 共同的数据结构

字段统一定义在主脚本的 `USER_OPTIONS` 中。Clash Party 直接执行主脚本；独立生成器把主机文件的 `options` 注入这同一套参数，再调用主脚本。`host.location` 等既有简写可继续转换到对应参数，输入冲突需要明确报告。以下列出此次重构涉及的字段，已有 IPv6、进程、Tailscale 和测速参数继续保留。

| 字段 | 含义 |
|---|---|
| `location` | `cn` 或 `overseas`；只影响默认出口、家宽路径顺序和 DNS，不代替业务分类 |
| `nodes` | 自定义节点数组；没有自定义节点就填 `[]`，订阅节点由订阅自动导入 |
| `roles` | 用节点 ID 绑定用途；不重复保存节点凭证 |
| `defaults` | 生成配置的初始选择和缺少家宽时的 AI 策略，不强制覆盖客户端已保存的选择 |

### 节点字段

每个节点有稳定且唯一的 `id`、用于显示的 `name`，以及协议所需的 `type`、`server`、`port`、认证等字段。修改显示名称不改变角色引用。节点 ID 与订阅自动生成的 ID 必须隔离命名空间，不能互相覆盖。

- `interfaceName`：可选，本机真实网卡名。Windows、Linux、macOS 分别按实际网卡填写，不能把某台主机的网卡名当成跨平台默认值。
- `via`：可选，固定上级节点 ID 或策略组名称。引用必须能唯一解析；歧义、缺失或循环时报错。`via: "DIRECT"` 表示直接连接代理服务器。
- 订阅和自定义普通节点默认通过前置组连接；该组默认 DIRECT，是否增加一跳只由组内选择控制。专用节点保持直接连接，家宽直连和链式路径由家宽角色统一生成。
- 命令行生成器额外支持 `secret: "变量名"` 和 `optional: true`。它们属于输入适配，不作为 Mihomo 节点参数输出。
- 协议字段仍按对应 Mihomo 协议透传；`udp` 只有明确为 `true` 才声明支持。全协议能力必须同时检查完整上级链路。

### 用途绑定

| 字段 | 形式 | 用途 |
|---|---|---|
| `roles.general` | `{ subscriptions: true, nodes: [] }` | 普通出口允许使用订阅，以及明确列出的自定义节点 |
| `roles.domestic` | 节点 ID 数组 | 国内业务出口；不得按 IP 或名字自动推断授权 |
| `roles.home` | 节点 ID 数组 | 家宽出口，可以没有、一个或多个；为每个节点生成直连和可用的链式路径 |
| `roles.front` | `{ subscriptions: true, nodes: [] }` | 前置候选；订阅仍受前置过滤和链路安全检查约束 |

不配置 `roles` 时，仅订阅进入普通出口和前置候选；自定义节点必须显式绑定用途。未被任何用途或明确链路引用的自定义节点报错，避免填写成功却完全不生效。

同一个 ID 可以同时出现在国内、前置和普通出口中；只有明确进入 `general.nodes` 的自定义节点才进入通用候选。不能因为允许当前置，就自动加入 AI、媒体或家宽跳板。

前置角色只增加候选，不启用前置。候选必须本机可直接连接，不能再次依赖前置组或其他上级。订阅和普通自定义节点已由脚本自动绑定前置时，生成 `⤴` 直连副本；原先自带或显式指定的上级不能强行删除。网卡或 Tailnet 路由存在不等于实际连通，仍需客户端验证。

### 默认值与缺少配置

- `defaults.front`：默认 `DIRECT`。填写节点 ID 时，该节点必须已是前置候选。
- `defaults.unmatched`：默认 `节点选择`，生成最终 `MATCH`；不再单独创建兜底组。这与当前 cn 兜底可能走国内直连的行为不同，迁移时必须明确提示。
- `defaults.aiWithoutHome`：默认 `REJECT`。用户可以明确改为 `节点选择` 等合法出口，允许没有家宽时使用普通节点；不能静默将住宅出口替换成机房 IP。
- cn 的国内业务默认 DIRECT，overseas 默认第一个已配置的国内节点。没有国内节点时回到 DIRECT，并明确提示没有回国出口。
- 没有家宽节点时，不生成家宽组和家宽跳板；AI 按 `aiWithoutHome` 处理。没有国内或家宽配置不影响其他用途的节点。
- `optional: true` 仅表示凭证缺失时允许跳过该节点及其角色，必须报告跳过结果；角色里写错 ID、密码不完整或引用循环仍然报错。
- `select` 的候选顺序只代表初始选择，不代表自动故障切换。运行时还需核对客户端实际选择与缓存。

## 主脚本顶部：配置示意

以下展示重构后的 `完全覆写.js` 用户参数区。只列出相关字段，实际文件继续保留其他已有参数。`nodes`、`roles` 和 `defaults` 需要在主脚本实现后才会生效；不是新增一个先执行的脚本。Clash Party 下订阅由客户端提供，无需再次填写订阅 URL。

```javascript
var USER_OPTIONS = {
    location: "cn",
    enableIPv6: false,
    nodes: [
      {
        id: "cn-exit",
        name: "国内节点",
        type: "socks5",
        server: "替换为国内代理地址",
        port: 1080,
        username: "替换为用户名",
        password: "替换为密码"
      },
      {
        id: "home-us",
        name: "美国家宽",
        type: "http",
        server: "替换为家宽代理地址",
        port: 8080,
        username: "替换为用户名",
        password: "替换为密码"
      }
    ],
    roles: {
      general: { subscriptions: true, nodes: [] },
      domestic: ["cn-exit"],
      home: ["home-us"],
      front: { subscriptions: true, nodes: ["cn-exit"] }
    },
    defaults: {
      front: "DIRECT",
      unmatched: "节点选择",
      aiWithoutHome: "REJECT"
    }
};
```

国内组在国内电脑上默认 DIRECT，国内节点只是可选项。前置仍默认 DIRECT，要启用时在前置组选择国内节点。家宽优先链式路径，AI 优先家宽。

需要把个人凭证与共享主脚本分开时，可以沿用可选的出口凭证注入方式。输入适配与冲突检查仍在主脚本内完成，用户不必同时维护两份相同节点。

不需要认证时删掉 `username`、`password`。增加公司出口时，在 `nodes` 追加一个唯一 ID 的节点，再按用途加入 `general.nodes` 或 `front.nodes`；如果只供公司域名使用，应由自定义业务组显式引用，不加入通用角色。公司专用规则仍沿用自定义规则组职责，本次不再引入另一套规则语法。

## 无 Clash Party：调用同一主脚本

以下是未来 `hosts/overseas-cloud.example.js` 的结构示意。`options` 是主脚本 `USER_OPTIONS` 的外部赋值方式；生成器只解析凭证和准备参数。订阅、监听端口等由独立运行环境提供：

```javascript
module.exports = {
  subscriptions: [
    { name: "机场", url: "secret:SUB_URL_MAIN" }
  ],
  options: {
    location: "overseas",
    nodes: [
      { id: "cn-exit", name: "国内节点", secret: "CN_EXIT_URL", optional: true },
      { id: "home-us", name: "美国家宽", secret: "HOME_PROXY_URL", optional: true }
    ],
    roles: {
      general: { subscriptions: true, nodes: [] },
      domestic: ["cn-exit"],
      home: ["home-us"],
      front: { subscriptions: true, nodes: ["cn-exit"] }
    },
    defaults: {
      front: "DIRECT",
      unmatched: "节点选择",
      aiWithoutHome: "REJECT"
    }
  },
  runtime: {
    mixedPort: 7890,
    bindAddress: "127.0.0.1",
    allowLan: false,
    tun: false
  }
};
```

本地 `secrets.env` 对应填写：

```dotenv
SUB_URL_MAIN=https://example.invalid/subscription
CN_EXIT_URL=socks5://user:password@203.0.113.88:1080
HOME_PROXY_URL=http://user:password@198.51.100.20:8080
```

这里的域名、IP 和密码均为文档占位值。URI 的用户名、密码含 `@`、`:` 等特殊字符时需要按 URI 规则编码。Clash Party 的 JavaScriptCore 不读取系统环境变量或 `secrets.env`，直接填写节点参数，不使用 `secret` 语法。

生成的 YAML 含真实凭证，即使原始主机文件只保存变量引用，也必须保护输出文件。生成器只生成和校验配置，不负责部署或客户端选择恢复。

## 不配置和多节点怎么处理

| 需求 | 配置方式 |
|---|---|
| 只有订阅 | `nodes: []`；不填写国内、家宽角色；明确设置是否允许 AI 使用节点选择 |
| 没有国内节点 | `roles.domestic: []`，前置里也不引用它 |
| 没有家宽 | `roles.home: []`，按 `aiWithoutHome` 明确选择拒绝或普通出口 |
| 多个公司出口 | 每个节点一个唯一 ID，按需加入普通出口或公司专用组 |
| 多个家宽 | `roles.home` 填写多个 ID；共享家宽组列出各自直连、链式路径，保持单节点稳定引用 |
| 国内节点同时当前置 | 同一个 ID 同时填入 `domestic` 和 `front.nodes`，不复制节点 |
| 使用订阅当前置 | `front.subscriptions: true`，从安全的 `⤴` 副本中选择 |

以上允许空角色，不意味着完全没有出口也能生成配置。无订阅、无自定义节点且没有合法业务出口时，仍应明确报错。

## 实施与兼容要求

1. 首先在 `完全覆写.js` 实现统一数据模型、参数和旧入口适配，并直接测试 `main(config)`；同一节点多角色只合并角色，不重复生成物理节点。
2. `_homeProxy`、`_frontProxy`、`_customProxies`、现有 headless `roles.*` 通过适配器进入统一模型。新旧定义冲突、ID 或名称重复时明确报错，不能静默覆盖或偷偷开放专用节点。
3. 主脚本的功能通过回归后，再让独立生成器准备同样的参数并更新 host 样本。家宽跳板偏好等路由逻辑移回主脚本，生成器不得在输出阶段另行实现一套分流行为。
4. 更新策略组时同步迁移规则、DNS、Sniffer、QUIC、旧组名引用和已保存的选择；保留 Tailscale、内网、进程和 IPv6 默认关闭等特殊策略。
5. 回归覆盖 cn/overseas、纯订阅、单个及多个自定义/家宽节点、缺少可选凭证、角色隔离、前置副本、固定上级、缺失引用、循环和完整链路 UDP 能力。同一订阅和有效参数直接执行主脚本、通过独立生成器执行，得到的业务组、链路、规则和 DNS 应一致，主机监听参数单独比较。
6. 用本地占位凭证测试，不在仓库、日志或调查记录里保存真实代理地址与密码。静态配置校验不代替客户端重载和实际出口验证。

第一阶段不实施按地区、节点名称或假定可达性自动猜测链路，也不引入复杂标签选择器。旧[节点清单设计](./节点清单设计.md)中的自动推导、标签和网卡别名属于后续提案，不是本参考要求用户填写的字段。
