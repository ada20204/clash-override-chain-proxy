# 社区规则维护与调研记录

本文件是后续更新和排查的起点。先阅读最近的调查记录、来源清单和同步历史，再按现有快照做增量修改；不要重新从零维护整套服务域名。

## 维护目标

社区负责发现和补齐服务域名，项目负责决定业务出口、DNS、协议处理及规则优先级。按服务用途分流，同一厂商的 AI 产品与普通产品可以使用不同策略组。

代理组、凭证、家宽链路、Tailscale 和进程规则仍由主覆写统一生成。社区规则在维护阶段下载并内嵌；Clash Party 执行覆写时无需联网下载这些规则文件。

## 文件与职责

| 文件 | 用途 |
|---|---|
| `rules/community-sources.json` | 上游仓库、文件路径、格式、策略组映射、过滤理由、必需条目和分类边界样例 |
| `rules/community.snapshot.json` | 固定到具体上游提交的完整规则快照，包含原始文件 URL、SHA-256 和规范化条目 |
| `rules/community-update-history.json` | 追加式历史：上游版本、原始增删、实际分类增删、过滤原因和策略文件摘要 |
| `scripts/sync-community-rules.js` | 下载、解析、过滤、检查、增量比较和生成工具 |
| `scripts/rule-routing-audit.js` | 检查显式规则的首条命中，覆盖 TCP/UDP 和精确域名边界 |
| `src/完全覆写.js` | 自包含的运行脚本，包含生成区段与本地策略 |
| `tests/validate-community.js` | 来源解析、无效更新拦截、确定性生成和增量增删回归 |
| `tests/validate-direct.js` | 主覆写的功能、DNS、QUIC、分流、进程和链路回归 |

生成区段不能手工修改。社区快照也不应当作手写清单编辑；来源变更通过 `--refresh` 获取，分类策略变更通过清单和 `--render` 生效。

## 分类边界

| 服务 | 目标 |
|---|---|
| Claude、ChatGPT、Gemini、AI Studio、Antigravity、Cursor、Grok 等海外 AI | `🤖 AI Agent` |
| Muse、Meta AI、Llama、Meta 专用 AI 开发入口 | `🤖 AI Agent` |
| Microsoft Copilot 与 GitHub Copilot 的专用域名 | `🤖 AI Agent` |
| Facebook、Instagram、WhatsApp、Messenger、Threads 的普通业务 | `🌍 国际媒体` |
| YouTube、Netflix、Disney、Spotify、Twitter、Reddit、TikTok、BBC | `🌍 国际媒体` |
| Telegram、Discord | `📲 Telegram` |
| GitHub 仓库、普通下载、镜像与开发资源 | `🐙 GitHub` |
| 普通微软、Apple、游戏平台 | 保持原有功能组和本地策略 |

`meta`、`github` 等总集合会包含 AI 子服务。AI 专用规则优先匹配，普通集合中相同条目通过显式 `aiOverrides` 排除。未登记的跨组冲突会停止生成，维护者需要确认业务用途后再处理。

YouTube 在共享 Google API、头像资源上的规则先于 Google 总集合。Google 账号和 AI 的出口一致性沿用 `googleTrafficConsistency`，YouTube 内容与 Google Play/FCM 保留已有例外。

`DOMAIN` 保持精确匹配；`DOMAIN-SUFFIX` 保持后缀匹配。它们分别生成精确或后缀 DNS、Sniffer 和 AI UDP/443 拒绝规则。不能把社区给出的专用 CDN 主机扩大为整个 CDN 的后缀。

共享基础设施不通过全局域名规则自动送入 AI Agent。独立 AI 应用仍由进程规则覆盖；普通浏览器中复用同一个 API/登录/CDN 主机的不同业务，无法仅靠域名区分。

## 日常增量更新

先检查工作区，查看最近一次历史并预览变化：

```bash
git status -sb
node scripts/sync-community-rules.js --dry-run
```

`--dry-run` 会下载和校验当前上游，输出各来源的新增/删除、各生效分类的新增/删除及过滤理由，不写项目文件。注意异常的大范围删除、整个厂商或共享平台的加入、精确匹配改为后缀匹配，以及新服务是否在普通集合中也出现。

确认变更后运行：

```bash
node scripts/sync-community-rules.js --refresh
node scripts/sync-community-rules.js --check
node --check src/完全覆写.js
npm test
git diff --stat
```

工具先查询每个仓库分支的提交 SHA，然后从固定 SHA 下载所有文件，避免同一批文件跨版本。下载、解析、关键条目或规则边界校验失败时，不替换已有快照或覆写脚本。

`--check` 完全离线：确认快照与来源定义一致、生成区段可重现、主脚本生成后的显式规则符合边界。上游分支提交变化但规则内容不变时，快照记录新版本，增量历史不会制造重复的规则变更。

仅修改本地过滤、分类边界或在离线环境重建时：

```bash
node scripts/sync-community-rules.js --render
node scripts/sync-community-rules.js --check
node tests/validate-community.js
node tests/validate-direct.js
```

`--render` 使用现有快照；若修改了来源文件、仓库或格式，则必须重新 `--refresh`。重复生成不会加入重复规则，也不会因为时间戳让生成区段产生无意义变化。

已迁移的 AI、媒体、Telegram/Discord、GitHub 基础清单不再在手写区重复保留，便于上游删除真正生效。本地手写区只保留独立补充，例如 Anthropic 专用 Auth0/CDN/站点、Google 账号一致性、Kiro 专用端点及既有的 `byteoversea.com` 媒体例外；上游删除相关条目时，仍需确认是否与这些明确的本地策略重叠。

目前通过维护者或代理执行上述命令更新，没有新增自动提交或自动推送工作流。

## 发现新 Agent 或误分类时

1. 核对产品官网、公告和跳转关系，确定域名归属；不要因为域名包含 `ai`、`agent` 或产品名称就自动归类。
2. 查看客户端实际连接：记录进程、目标域名、端口/协议、首条命中规则及最终选择的节点。检查浏览器强制代理开关和当前模式。
3. 查社区的具体服务集合和对应文件的提交历史。区分实际内容更新与每天没有内容变化的定时提交；仓库整体更新频繁不代表某个分类更新频繁。
4. 区分主站、专用 API、文件/CDN、登录和共享基础设施。父域属于普通产品时，AI 的精确子域规则应放在它之前。
5. 在来源清单中增加合适来源或调整有理由的排除/覆盖策略；新格式必须先增加解析和失败场景测试。现有解析器仅接受明确的域名规则，IP、ASN、进程、关键词、正则和未知格式不会静默转为域名。
6. 在 `routingCases` 和回归测试中同时增加正例和反例。例如 Muse 应走 AI，Facebook 应走媒体；Copilot 应走 AI，普通 GitHub 应走 GitHub。
7. 确认新增 AI 域名同时进入 DNS、Sniffer、QUIC，重跑离线检查及测试。
8. 在本文件追加日期小节，保留官网和上游提交链接、问题原因、修复理由、测试与尚未验证部分。

参考页检查可以使用 `node scripts/check-claude-rules.js`。该工具会读取本地 Anthropic 补充和实际内嵌 AI 规则，保留精确/后缀区别；它是查漏辅助，不会自动把共享基础设施加入 AI。

## 2026-10-06：Clash Party 实际加载与流量验证

### 检查方法

用户更新客户端中的覆写后，先比较项目 `src/完全覆写.js` 与客户端 `override` 目录中已启用脚本的文件内容，再检查 `work/config.yaml` 和当日客户端重载日志。此次两份脚本逐字节一致，日志记录北京时间 `00:08:03` 热重载完成。

Windows 客户端此次使用命名管道控制器，`external-controller` 为空不表示控制接口不可用。可从当日 Clash Party 日志或 `Get-ChildItem -LiteralPath '\\.\pipe\'` 找到 `MihomoParty` 管道；管道名称含当前进程信息，不能沿用上次的固定名称。使用 Node.js `http.get({ socketPath: 当前管道路径, path: 接口路径 })` 读取以下接口，不需要修改模式或所选节点：

- `/version`：实际运行的内核版本。
- `/configs`：实际模式、代理端口和 TUN 开关。
- `/rules`：内核已加载规则、是否禁用，以及命中次数与时间。
- `/proxies`：各组当前的 `now` 选择，逐级追踪最终节点。
- `/connections`：已有连接的域名、命中规则及出口链路。

对代表域名通过本机 HTTP 代理发送不跟随跳转的 HEAD 请求，再核对 `/rules` 命中计数和当日 core 日志。请求示例：`curl.exe --head --proxy http://127.0.0.1:7890 --connect-timeout 8 --max-time 15 https://muse.ai/`。下次使用前先确认当前代理端口。控制器和连接输出只保留所需字段，不将凭证、订阅链接、完整连接列表或出口 IP 写入调查记录。
