# Clash 完全覆写脚本低门槛配置教程

这篇教程面向第一次使用 Clash Party / Mihomo Party 覆写的人。你不需要理解脚本源码，只要按自己的情况导入文件，并修改少量配置项即可。

> 本页是当前可执行配置；尚未实现的重构提案与历史资料请从[文档索引](./README.md)进入。

## 这个脚本解决什么问题

这个项目会在你的订阅配置上自动补齐代理组、分流规则和 DNS 配置。最低门槛用法是只导入 `完全覆写.js`，不配置家宽 IP、不配置自定义出口，也可以获得功能组、域名规则、国内直连和可手动选择的 `🐟 兜底`。

| 场景 | 脚本会怎么处理 |
|---|---|
| YouTube、Netflix、Twitter、Spotify 等 | 走 `🌍 国际媒体` 组 |
| Telegram、Discord | 走 `📲 Telegram` 组 |
| GitHub 普通业务 | 走 `🐙 GitHub` 组；GitHub Copilot 专用端点走 `🤖 AI Agent` |
| Microsoft、Office、Windows 更新、Xbox | 走 `Ⓜ️ 微软服务` 组，默认直连，可切 `🇨🇳 国内` |
| Bing、`visualstudio.com`、`vscode.dev`、npm 等指定开发域名 | TCP/443 走 `节点选择`；其他协议/端口在有合格候选时走全协议回退 |
| Steam、Epic、`nintendo.com`、PlayStation | 走 `🎮 游戏平台` 组；`nintendo.co.jp` 等日本服务另走隐藏的 `🇯🇵 日本服务` |
| Apple、iCloud、App Store | 走 `🍎 Apple` 组，默认直连，可切 `🇨🇳 国内` |
| 国内网站和国内 IP | 走 `🇨🇳 国内`（cn 默认直连，overseas 默认回国出口）；`GEOIP,cn` 会解析域名 |
| 局域网 / 私网段 | 走 `🎯 直连` |
| Claude、ChatGPT、Cursor、Codex 等 AI 工具 | 走独立的 `🤖 AI Agent` 组 |
| AI 网站的 HTTP/3 / QUIC | 默认拒绝 UDP/443，促使支持回退的客户端改用 HTTPS/TCP，避免不支持 UDP 的出口被跳过 |
| 浏览器 WebRTC | 默认拒绝常用 STUN UDP 端口；不是对全部 WebRTC 流量或泄漏的完整防护 |

代理服务器防回环、Tailscale 目的地及私网规则先于浏览器/AI 进程规则，避免显式 HTTP/SOCKS 代理入口把内网请求送到外部出口。明确配置的私网业务 CIDR 可在通用私网规则前生效，但不能越过代理服务器和 Tailnet 保护；公网或跨出私网的过宽 CIDR 不会提前。建议网段例外带 `no-resolve`，以免额外触发域名解析。

上表描述普通域名分类，不保证同一应用的全部连接都走同一组；进程规则、检测站和安全例外可能先命中。国内业务主要依赖 `GEOSITE,cn` 与 `GEOIP,cn`，实际覆盖取决于本机数据版本。显式保留 `rivotek.com` 走国内组与国内 DNS，`typeless.com` 使用海外 DNS、业务连接直连，不再重复维护整套国内产品域名表。

## 先选你的使用模式

| 你想实现什么 | 需要导入哪些文件 | 适合谁 |
|---|---|---|
| 只想自动分流，不折腾家宽 IP | 只导入 `完全覆写.js` | 新手、普通代理订阅用户 |
| 想解决本机网络到订阅节点污染或超时 | 在 `🔗 前置` 选择可直连的候选；自定义节点用 `出口IP凭证.js` 配置 | 有一级代理或国内云服务器代理的人 |
| 想让 AI 工具走美国静态家庭 IP | 先导入 `出口IP凭证.js`，再导入 `完全覆写.js` | 有静态家庭 IP 或家宽代理的人 |
| 想额外加入自己的 HTTP/SOCKS5 出口节点 | 先导入 `出口IP凭证.js`，再导入 `完全覆写.js` | 有备用出口、自建代理的人 |
| 没有订阅，只想使用公司节点/固定 IP | 导入 `无订阅基础配置.yaml`，再导入 `出口IP凭证.js` 和 `完全覆写.js` | dedicated 公司代理、静态 IP 用户 |

已有节点可直接在前置组选择，不必再加前置脚本。家宽、自定义节点及业务规则统一放在一个凭证文件，顺序是：

```text
1. 出口IP凭证.js     （可选，家宽、自定义/前置节点、专用业务规则）
2. 完全覆写.js       （必选）
```

主脚本必须最后执行。凭证文件把数据注入 `config`，`完全覆写.js` 再读取并生成节点、代理组和规则。下文各场景示例应合并进同一个 `main(config)`，每种数组只赋值一次，不要整段重复粘贴。

## 方式一：纯分流模式

适合只想让订阅配置更好用的人：自动分组、自动分流、国内直连。

1. 打开仓库里的 `src/完全覆写.js`
2. 下载到本地
3. 在 Clash Party / Mihomo Party 的「覆写」列表里新增 JavaScript 覆写
4. 选择或粘贴 `完全覆写.js`
5. 启用覆写，回到订阅配置重新应用

## 方式二：无订阅模式

适合没有机场订阅，只想使用 dedicated 公司代理、自建 HTTP/SOCKS5 节点或固定 IP 的人。

1. 导入 [`src/无订阅基础配置.yaml`](../src/无订阅基础配置.yaml) 作为基础配置
2. 复制 [`src/出口IP凭证_样本.js`](../src/出口IP凭证_样本.js)
3. 重命名为 `出口IP凭证.js`
4. 在 `出口IP凭证.js` 里填入 `config._customProxies` 或 `config._homeProxy`
5. 覆写顺序设置为：`出口IP凭证.js` → `完全覆写.js`

无订阅模式不会生成地区组或 `自动选择`。仍需至少配置 `_customProxies`、`_homeProxy` 或 `_customRuleGroups` 中的一项，否则报错。仅配置使用 `DIRECT` 的自定义业务组也可运行；只有旧 `_frontProxy` 不满足这一条件。


自定义业务组在国内/国外/兜底之前；隐藏监控组及全协议回退组按选项和节点能力生成，未列在上面。

## 方式三：配置前置代理

前置代理适合本机所在网络到订阅节点 DNS 污染严重、晚高峰 URLTest 大面积超时，或者希望先从一级代理/国内云服务器出站，再连接订阅里的外部节点。

订阅和普通自定义节点默认跟随 `🔗 前置`，不需要逐个填写 `useFrontProxy` / `allowAsFront`：在组里选 `DIRECT` 就不加前置，选代理就增加一跳。前置候选使用 `⤴ 原名` 直连副本，避免节点再次依赖前置组。

专用节点不会自动加入候选。比如国内节点也要作为前置，在 `完全覆写.js` 的 `USER_OPTIONS` 中填写：

```javascript
front: { include: ["阿里云回国"], excludePorts: [], excludeKeywords: [], prefer: [] },
```

`include` 只追加候选，不自动选中，也不让专用节点进入普通出口组。必须填写已有的节点名，不能填策略组；不存在、被过滤或已有显式代理上游的节点会报错。普通节点不需要写进 `include`。规则模式下前置检测看 `ip.sb`；`ipip.net` 直连，显示本机环境出口。

如果候选里还没有需要的代理，在 `出口IP凭证.js` 的 `_customProxies` 数组追加它即可，不用另建文件。普通节点会自动成为前置候选；仅供前置使用的节点设 `dedicated: true`，再通过上述 `front.include` 授权。

选择前置后，订阅和普通自定义节点默认先走该前置，URLTest 也使用相同链路。家宽真直连和 DIRECT 不受影响；家宽链式仍经家宽跳板。专用节点保持直接拨号，显式 `via` 上游不变。

旧 `_frontProxy` 仍兼容：可把旧文件中的配置原样移入 `出口IP凭证.js` 的 `main(config)`，保留原来的默认选中行为，然后停用旧文件。不要再在 `_customProxies` 定义同名节点。新配置只用数组与前置组，不再单独维护前置样本。

迁移旧配置时，显式 `useFrontProxy: false` 仍固定直连，`true` 仍跟随前置；旧 `allowAsFront: true` 仍保持直接拨号并授予前置候选资格。要改用统一控制，删除旧字段，专用节点用 `front.include` 授权。只有特殊固定链路才填写 `via: "DIRECT"` 或 `via: "上游名称"`。客户端缓存的前置选择仍需在界面确认，不会因为更新脚本就强制切回 DIRECT。

> 旧 `_frontProxy` 不进入 `节点选择` 或 `🤖 AI Agent`，但会出现在 `GLOBAL`。在 GLOBAL 直接选择它，是把它当成最终出口，不是保留原出口再加一跳。要保留最终出口，应在 `🔗 前置` 选择前置节点；`GLOBAL → DIRECT` 始终真实直连。

## 方式四：配置美国静态家庭 IP

适合你有一个自己的家宽 HTTP/SOCKS5 代理，或者通过静态住宅 IP 服务购买了固定美国出口，并希望 AI 工具流量走这个出口。

配置后，脚本会新增：

| 新增内容 | 作用 |
|---|---|
| `家宽IP` 节点 | 你的家宽 HTTP/SOCKS5 出口，真直连，不挂 `dialer-proxy` |
| `家宽IP链式` 节点 | 有订阅或自定义跳板时自动生成，先走 `🔗 家宽跳板` 再访问家宽出口 |
| `🔗 家宽跳板` 组 | 仅在有跳板候选时生成，决定链式家宽的上游 |
| `🏠 家宽IP` 组 | 可在 `🤖 AI Agent`、`节点选择` 和 `GLOBAL` 中选择 |

### 复制凭证样本

复制 [`src/出口IP凭证_样本.js`](../src/出口IP凭证_样本.js)，重命名为：

```text
出口IP凭证.js
```

### 填写家宽 IP 信息

打开 `出口IP凭证.js`，找到 `config._homeProxy`，取消注释并填入真实信息：

```javascript
function main(config) {
  config._homeProxy = {
    type: "socks5",
    server: "你的家宽IP或域名",
    port: 1080,
    username: "你的账号",
    password: "你的密码"
  };

  return config;
}
```

字段说明：

| 字段 | 怎么填 |
|---|---|
| `type` | 本教程示例为 `http` 或 `socks5`；原生协议节点应填写对应的 Mihomo 类型和字段 |
| `server` | 家宽代理的 IP 或域名 |
| `port` | 家宽代理端口，例如 `1080`、`7890` |
| `username` | 如果代理需要账号，再填写 |
| `password` | 如果代理需要密码，再填写 |
| `interfaceName` / `interface-name` | 可选，本机网卡名；两种家宽节点均保留该字段 |

不要把填写了账号密码的 `出口IP凭证.js` 上传到公开仓库。这个文件应该只保存在你自己的电脑里。

## 方式五：添加自定义出口节点

如果你还有普通 HTTP/SOCKS5 出口，可以写到 `config._customProxies`。这些节点会被注入到代理节点里，并出现在 `节点选择` 和相关功能组中。只允许公司域名或内网网段使用的代理不要使用这种默认写法。

示例：

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "自定义出口",
      type: "http",
      server: "192.168.88.10", // 示例：通过本机路由可达的子网代理
      port: 3128,
      via: "DIRECT", // 固定经本机路由连接此内网代理，不跟随前置
      // 可选：如果这个出口在 Tailscale subnet 内，填 Tailscale 网卡名，例如 "utun4"
      interfaceName: ""
    }
  ];

  return config;
}
```

上例因使用内网代理而固定 `via: "DIRECT"`；普通公网出口如需跟随前置，省略 `via` 即可。`interfaceName` 只绑定网卡，不等于取消前置。如果代理通过 Tailscale subnet 可达，应先确认系统路由，再按需绑定接口。macOS 可执行 `route -n get 代理IP` 查看 `interface`，不要照抄其他机器的接口名。

辅助脚本在 macOS/Linux 可自动探测网卡名；Windows 需要显式传入 `--interface`。先预览：

```bash
node scripts/update-interface-name.js \
  --file "/path/to/出口IP凭证.js" \
  --server 192.168.88.10
```

确认无误后写入：

```bash
node scripts/update-interface-name.js \
  --file "/path/to/出口IP凭证.js" \
  --server 192.168.88.10 \
  --write
```

Windows 示例（将 `Tailscale` 换成本机实际网卡名）：

```powershell
Get-NetAdapter | Select-Object Name, InterfaceDescription, Status
node scripts/update-interface-name.js --file "C:/path/to/出口IP凭证.js" --server 192.168.88.10 --interface "Tailscale"
```

先执行 `npm ci` 安装维护工具依赖，检查 dry-run 摘要，再追加 `--write`。工具通过语法树定位唯一的静态 `server` 属性，不执行凭证代码、不打印密码；同一地址匹配多个对象、重复字段或语法错误时拒绝写入。保留原有 `interfaceName` / `interface-name` 字段风格，写入前再做语法校验。指定网卡不代表该网卡到目标代理一定可达，仍需测试实际连接。

如果自定义出口也需要账号密码，继续追加：

```javascript
{
  name: "带认证的出口",
  type: "http",
  server: "example.com",
  port: 3128,
  username: "你的账号",
  password: "你的密码"
}
```

### 自定义规则组

如果某些固定域名或网段需要走一个单独目标，但这个目标不应该作为普通出口出现在 `节点选择` 里，可以使用 `config._customRuleGroups`。这类配置适合“指定规则 → 指定策略组”的场景。

在同一个 `出口IP凭证.js` 的 `main(config)` 内添加 `_customRuleGroups`。建议引用 `_customProxies` 或订阅里已有的节点；也保留内嵌 `proxy` 写法，例如：

```javascript
function main(config) {
  config._customRuleGroups = [
    {
      name: "自定义业务",
      proxy: {
        name: "自定义业务节点",
        type: "socks5",
        server: "127.0.0.1",
        port: 10880
      },
      rules: [
        "DOMAIN,service.example.test",
        "DOMAIN-SUFFIX,internal.example.test"
      ],
      testUrl: "http://connect.rom.miui.com/generate_204"
    }
  ];

  return config;
}
```

脚本会生成 `自定义业务` 策略组，并把上面的规则指向该组。自定义规则组的测速地址按“分组 `testUrl` → 全局 `USER_OPTIONS.urlTestProbeUrl` → 脚本内置默认值”的顺序取值。`proxy` 是可选的；如果目标节点已经存在，也可以写：

```javascript
proxies: ["已有节点名"]
```

或者在特定机器上直接走系统网络：

```javascript
proxies: ["DIRECT"]
```

`_customRuleGroups` 也支持无订阅模式。导入空 YAML、含自定义业务配置的 `出口IP凭证.js` 和 `完全覆写.js` 即可，不需要另一个自定义规则组文件。

自定义规则只能覆盖普通业务分类，不能覆盖代理服务器地址直连、Tailnet、IP 检测路由、Google/AI 一致性、AI QUIC 或 WebRTC 防泄漏规则。若自定义规则与这些受保护规则使用相同的类型和匹配值，完全覆写会显示冲突规则并停止生成配置；应缩小自定义域名或网段，而不是绕过安全规则。

### Tailscale 子网内的代理节点

这里指通过 Tailscale subnet router 能访问到的 HTTP/SOCKS5 代理服务器，不是“公司业务专用出口”。链路是 `本机 → Tailscale 子网路由器 → 子网内代理 → 目标服务`。子网路由与访问权限必须先配置好，凭证脚本不会代替这些设置，参见 [Tailscale 子网路由文档](https://tailscale.com/docs/features/subnet-routers)。

`server` 填代理实际监听的子网 IP，不要默认填写子网路由器的 `100.x` 地址。`via: "DIRECT"` 让本机通过系统路由连接它，不跟随 `🔗 前置`；这里 DIRECT 不等于绕过 Tailscale。`interfaceName` 按本机实际网卡填写，Windows 常见为 `Tailscale`，其他系统不要照搬。

节点的位置与用途分开配置。以下保留 `dedicated: true` 的专用示例，仅让指定业务使用它；域名和 `198.51.100.0/24` 都是文档占位目标，需替换为实际业务，而非照抄代理所在子网：

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "Tailscale子网代理",
      dedicated: true,
      type: "http",
      server: "192.168.88.10", // 替换为子网内代理的实际 IP
      port: 3128,
      via: "DIRECT",
      // 按本机实际接口填写，例如 Windows 的 "Tailscale"
      interfaceName: ""
    }
  ];

  config._customRuleGroups = [
    {
      name: "指定业务",
      proxies: ["Tailscale子网代理"],
      rules: [
        "DOMAIN-SUFFIX,internal.example.test",
        { type: "IP-CIDR", value: "198.51.100.0/24", option: "no-resolve" }
      ]
    }
  ];

  return config;
}
```

若希望它像其他出口一样出现在 `节点选择` 和功能组，把 `dedicated` 改成 `false`，保留 `via: "DIRECT"`，即可省略 `_customRuleGroups`。子网可达性不等于业务范围，不应因为代理位于 `10.x` 就把整个 `10.0.0.0/8` 交给它。直接访问子网设备仍由本机 Tailscale 路由处理，`tailscale.subnetCidrs` 也不是指定 HTTP 代理的开关。

专用节点只会出现在明确授权的组中，不会进入 `节点选择`、AI、媒体、GitHub、游戏平台、家宽跳板或 `GLOBAL`。如果没有被 `_customRuleGroups.proxies`、`USER_OPTIONS.domesticExit` 或 `front.include` 显式使用，脚本会拒绝生成配置，避免专用代理成为不可见的错误出口。旧 `allowAsFront` 授权仍兼容。

`dedicated` 不填写或为 `false` 时是普通节点，为 `true` 时是专用节点。旧 `scope: "ordinary" / "dedicated"` 继续兼容；同时填写时必须一致。布尔值不要加引号，`"false"` 等字符串会报错。

## AI Agent 组怎么理解

`🤖 AI Agent` 是 AI 域名和 AI 进程的独立策略组。它不直接列出总的 `自动选择`，但仍可经 `节点选择`、地区组或家宽跳板间接使用自动选择；这不保证出口固定。需要固定最终 IP 时，应明确选择固定出口并核对连接。

默认开启 `googleTrafficConsistency`：Gemini、AI Studio、Antigravity、Generative Language API、Google 账号和其余 Google 服务使用 `🤖 AI Agent`，保持登录与 AI 请求出口一致。YouTube 和 Google Play 优先进入 `🌍 国际媒体`，FCM 与 `mtalk.google.com:5228` 使用支持完整协议的出口。关闭该选项后，通用 Google 服务才恢复为 `节点选择`。

Sentry、Datadog、Intercom、Statsig、Stripe、WorkOS、SendGrid 等共享基础设施不会仅凭域名进入 AI Agent。Claude、ChatGPT、Cursor、Codex 等桌面应用和 CLI 仍通过进程规则进入 AI Agent，其他应用访问相同服务时继续使用普通分流。

有家宽 IP 时：

```text
🏠 家宽IP / 节点选择 / 地区组 / 普通自定义出口 / DIRECT
```

无家宽 IP 时：

```text
节点选择 / 地区组 / 普通自定义出口 / 订阅裸节点 / DIRECT
```

这里的关键点是：

- 有家宽 IP 时，AI Agent 里不展开订阅裸节点，避免高阶场景下列表过长
- 无家宽 IP 时，保留订阅裸节点，方便单独给 AI 选择某个支持 AI 的节点
- 地区组会保留，例如 `🇺🇸|美国`、`🇭🇰|香港`、`🇨🇳|台湾`
- 总的 `自动选择` 不放进 AI Agent，避免 AI 出口选择过于含糊

## 常用参数怎么改

修改 `完全覆写.js` 顶部 `USER_OPTIONS` 的对应项即可。以下是常用项摘录，不要用它覆盖整段参数：

```javascript
var USER_OPTIONS = {
  enableIPv6: false,
  location: "cn",
  domesticExit: [],
  frontGroup: true,
  front: { include: [], excludePorts: [], excludeKeywords: [], prefer: [] },
  autoSelectGroupName: "自动选择",
  urlTestProbeUrl: "",
  proxyProbeUrl: "https://www.gstatic.com/generate_204",
  overseasDnsTarget: "🤖 AI Agent",
  googleTrafficConsistency: true,
  directProxyServerRules: true,
  proxyServerResolvedIps: {},
  rejectAiQuic: true,
  rejectAppStoreQuic: true,
  rejectWebRtcUdp: true,
  fullProtocolFallback: null,
  enableChainRegionBrowserProcessProxy: false,
  enableChainRegionAiCliProcessProxy: true
};
```

一般只需要理解这几个：

| 参数 | 默认值 | 什么时候要改 |
|---|---:|---|
| `enableIPv6` | `false` | 同时控制全局和 DNS 的 IPv6；仅影响 Mihomo，不修改系统网卡或 Tailscale IPv6 |
| `autoSelectGroupName` | `自动选择` | 如果你的订阅自动测速组不叫「自动选择」，就改成你的组名 |
| `location` | `cn` | 本机所在位置，决定国内、国外、兜底组的默认选择；境外机器改为 `overseas`，见下方说明 |
| `domesticExit` | `[]` | `🇨🇳 国内` 组的候选节点/组名（第一个为 overseas 默认，cn 默认 DIRECT），另含 `DIRECT`、`节点选择` |
| `frontGroup` / `front.include` | `true` / `[]` | 默认使用前置选择组；include 额外授权专用节点，是否使用仍在组中手选 |
| `fullProtocolFallback` | `null` | 随 location：cn 开启、overseas 关闭；可明确设 true/false，候选必须整条链路支持 UDP |
| `urlTestProbeUrl` | 空（按 location） | 直连、Tailscale 监控和自定义业务组的界面健康检查地址；留空时 `cn` 用 `connect.rom.miui.com`，`overseas` 用 `cp.cloudflare.com` |
| `proxyProbeUrl` | `https://www.gstatic.com/generate_204` | 自动选择、地区组、节点选择、AI Agent 和家宽跳板等代理出海组的测速地址 |
| `overseasDnsTarget` | `🤖 AI Agent` | AI 的 DoH 出口，以及 cn 环境普通境外/未知域名的 DoH 出口；overseas 普通境外 DNS 使用 DIRECT，检测站另按清单处理 |
| `googleTrafficConsistency` | `true` | 将 Google 账号与 AI 服务统一出口；YouTube、Play、FCM 保留已有例外 |
| `directProxyServerRules` | `true` | 将代理节点服务器地址生成 `DIRECT` 规则，避免局域网中下游 Clash 再次代理节点连接 |
| `proxyServerResolvedIps` | `{}` | 当代理服务器写的是域名、而下游 Clash 只看到解析后的 IP 时，填写域名对应的 IP 列表，额外生成 `/32` 或 `/128 DIRECT` 规则 |
| `rejectAiQuic` | `true` | 拒绝 AI 域名 UDP/443，避免 HTTP 家宽出口不支持 UDP 时继续匹配到直连；整条链路支持 UDP 后才关闭 |
| `rejectAppStoreQuic` | `true` | 拒绝 `bag.itunes.apple.com` 的 UDP/443，让 App Store 在 TUN 下回退 HTTPS/TCP；只有确认 QUIC 可稳定通过时才关闭 |
| `rejectWebRtcUdp` | `true` | 拒绝常用 STUN UDP 端口 `3478`、`5349`、`19302`，防止 WebRTC 暴露本地公网 IP；需要实时音视频且整条链路支持 UDP 时才关闭 |
| `enableChainRegionBrowserProcessProxy` | `false` | 想让 Chrome、Edge、Dia、Atlas 等浏览器也走 AI Agent 时改为 `true` |
| `enableChainRegionAiCliProcessProxy` | `true` | 想让 Claude Code、Gemini CLI、Codex CLI 等 AI 命令行工具走 AI Agent，保持 `true` |

如果不知道要不要改，就先保持默认。默认配置更稳：AI 工具走独立组，浏览器不强制走 AI Agent。

例如代理服务器是 `edge.example.com`，而局域网下游的 Clash 已经只看到它解析后的地址时，可以这样填写：

```javascript
proxyServerResolvedIps: {
  "edge.example.com": ["203.0.113.10", "2001:db8::10"]
}
```

当这个域名的 IP 发生变化时，需要同步更新列表。Tailscale 自身的 STUN 流量已优先于浏览器 WebRTC 防泄漏规则处理，不需要在这里填写。

DNS 检测页显示的是递归 DNS 服务商的地址，不等于家宽出口 IP。cn 环境未知/境外域名默认经 AI Agent 查询；overseas 环境普通境外域名本机直连查询，AI 域名仍沿用 overseasDnsTarget，检测站另按清单解析。应结合所在地、浏览器安全 DNS 和实际连接判断，而不是只看 DNS 国家或是否等于家宽 IP。

### 境外使用（location）

脚本默认假设本机在中国大陆（`location: "cn"`）。国内、国外和兜底规则通过三个策略组统一管理，默认选择随位置变化。电脑或云主机在境外时设为 `overseas`：

| 项目 | `cn`（默认） | `overseas` |
|---|---|---|
| `GEOSITE,cn` / `GEOIP,cn` 与 rivotek.com 显式例外 | `🇨🇳 国内` 默认 `DIRECT` | `domesticExit` 第一个；未配置则 `DIRECT` |
| `🌐 国外`、无指定地区的代理型功能组 | 节点选择优先 | `DIRECT` 优先，节点选择保留可选 |
| `🐟 兜底`（MATCH） | `🇨🇳 国内` | `🌐 国外` |
| `🏠 家宽IP` 默认成员 | 链式在前 | 真直连在前 |
| 全协议回退（`fullProtocolFallback: null`） | 开启 | 关闭 |
| 未知/境外域名 DNS | DoH 经 `overseasDnsTarget` | DoH `#DIRECT` 本机解析 |
| 国内域名 DNS | 国内 DoH 直连 | 国内 DoH 经 `#🇨🇳 国内` |
| bootstrap / 代理服务器 / 直连 DNS | 223.5.5.5、AliDNS、DNSPod | 1.1.1.1、Google、Cloudflare；不生成 CN fallback |
| 直连测速地址 | `connect.rom.miui.com` | `cp.cloudflare.com`（`🇨🇳 国内` 组仍用国内地址） |

AI、Google 账号、Tailscale、代理服务器直连等受保护规则在两种位置下不变。回国节点建议写成 `dedicated: true`，默认只由 `🇨🇳 国内` 引用，不会进入节点选择、AI Agent 或家宽跳板。需要同时作为前置时，在 `front.include` 填同一名称：

```javascript
// 出口IP凭证.js
config._customProxies = [
  { name: "阿里云回国", dedicated: true, type: "socks5", server: "", port: 1080, udp: true }
];

// 完全覆写.js 顶部
location: "overseas",
domesticExit: ["阿里云回国"],
front: { include: ["阿里云回国"], excludePorts: [], excludeKeywords: [], prefer: [] },
```

节点只配置一份；国内组选择它时，国内业务从国内 IP 出口，前置组选择它时，它负责连接订阅或普通自定义节点，最终出口仍是后续节点或家宽。前置组不会因为国内组选择了它就跟着自动切换，也不能让该节点再依赖前置组，避免循环。国内节点不配置时，国内组默认 DIRECT；使用 headless 时可用 `optional: true` 跳过未配置的节点。

显式写在 `USER_OPTIONS` 里的 `urlTestProbeUrl`、`fullProtocolFallback` 始终优先于 location 默认值。

`location` 仅接受 `cn` 或 `overseas`，省略时默认 `cn`。`domesticExit` 可填写一个名称或名称数组，支持地区组、家宽组和自定义组，引用在所有组创建完成后检查。名称会去掉首尾空白并去重；空白名称和非字符串条目会报错。

`🇨🇳 国内` 的类型是 `select`，需要手动选择出口。候选顺序：overseas 为 `domesticExit...` → `DIRECT` → `节点选择`；cn 为 `DIRECT` → `domesticExit...` → `节点选择`。它不会在回国节点超时时自动接管；没有配置 `domesticExit` 时默认 `DIRECT`。

节点与组不可重名，自定义配置也不能覆盖受管组或已有节点。组成员与 `dialer-proxy` 会一起检查，出现不存在的引用或循环时，报错会显示相关名称及完整循环路径。

## 准备固定出口信息

脚本不依赖特定服务商，也不会把普通 IP 变成家宽 IP。需要先有一个可达的代理服务，确认协议、TLS 要求及认证方式，再填写本地凭证。只有家庭公网 IP、没有代理服务及端口时不能直接作为节点。

| 代理连接信息 | 填到脚本里的字段 |
|---|---|
| Host / Server | `server` |
| Port | `port` |
| Username | `username` |
| Password | `password` |

这些信息填在本地 `出口IP凭证.js`，不要写入共享主脚本或公开仓库。需要家宽直连/链式双路径时用 `_homeProxy`；作为普通出口时用 `_customProxies`。

### 先用命令测试代理是否可用

如果电脑上可以使用命令行，建议先测试一次，避免直接填进 Clash 后不好排查。

SOCKS5 示例：

```bash
curl --proxy socks5h://username:password@Host:Port https://ipapi.is/
```

HTTP 示例：

```bash
curl --proxy http://username:password@Host:Port https://ipapi.is/
```

把占位值替换为代理连接信息；Windows PowerShell 可使用 `curl.exe`。这类直接指定代理的命令只验证节点，不验证 Clash 分流。IP 属地是美国不能证明它是住宅 IP、长期静态或可用于特定 AI 服务。不要公开包含认证信息的命令历史、截图或日志。

## 如何配置美国 IP 节点

以下以美国家宽代理为例；其他地区的固定出口也使用相同字段。需要家宽组的真直连和链式双路径时，配置 `_homeProxy`。

### 第 1 步：创建 `出口IP凭证.js`

从仓库复制这个文件：

```text
src/出口IP凭证_样本.js
```

重命名为：

```text
出口IP凭证.js
```

这个文件只放在你本地电脑里，用来保存美国 IP 的 Host、Port、Username、Password。不要把填好密码的版本提交到 GitHub。

### 第 2 步：判断代理类型

按代理服务实际提供的连接方式填写，下面列出常见类型：

| 后台给出的类型 | `type` 应该填写 |
|---|---|
| SOCKS5 / Socks5 | `socks5` |
| HTTP | `http` |
| HTTPS（到代理服务器本身使用 TLS） | `http`，并设置 `tls: true` |

按服务商实际提供的协议填写。HTTPS 目标网站不等于 HTTPS 代理；SOCKS5 也不自动代表服务端及整条链路支持 UDP。

### 第 3 步：把美国 IP 填到 `config._homeProxy`

如果是 SOCKS5，就这样填：

```javascript
function main(config) {
  config._homeProxy = {
    type: "socks5",
    server: "代理服务器的 Host",
    port: 12345,
    username: "代理账号",
    password: "代理密码"
  };

  return config;
}
```

如果是 HTTP 代理，就这样填：

```javascript
function main(config) {
  config._homeProxy = {
    type: "http",
    server: "代理服务器的 Host",
    port: 12345,
    username: "代理账号",
    password: "代理密码"
  };

  return config;
}
```

注意：

- `server` 填 Host / Server，不要加 `http://` 或 `socks5://`
- `port` 是数字，不要加引号
- `username` 和 `password` 必须保留引号
- 本教程示例使用 `http` 或 `socks5`，应与实际服务协议一致；TLS 代理额外填写 `tls: true`

### 第 4 步：按顺序导入覆写

在 Clash Party / Mihomo Party 的「覆写」页面里，按下面顺序启用：

```text
1. 出口IP凭证.js
2. 完全覆写.js
```

有前置或自定义业务规则时仍然只用以上两个文件：相关节点和规则放在凭证文件里，前置在策略组选择。

导入后重新应用订阅配置。配置成功时，代理组里应该能看到：

```text
🤖 AI Agent
🏠 家宽IP
🔗 家宽跳板（存在可用跳板时）
```

### 第 5 步：在 AI Agent 里选择美国 IP

打开「代理组与节点」，找到：

```text
🤖 AI Agent
```

如果你已经配置了美国静态 IP，`🤖 AI Agent` 里应该可以选择：

```text
🏠 家宽IP
```

选择 `🏠 家宽IP` 后，Claude、ChatGPT、Cursor、Codex、Gemini CLI 等 AI 工具会优先走这个美国静态 IP。

### 可选：把美国 IP 当普通自定义节点

如果不需要家宽双路径，只想将它作为普通裸节点使用，可以写到 `_customProxies`。这不是唯一让它出现在 `节点选择` 的方式：`_homeProxy` 生成的家宽组也在 `节点选择` 和 `GLOBAL` 内。

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "美国静态IP",
      type: "socks5",
      server: "代理服务器的 Host",
      port: 12345,
      username: "代理账号",
      password: "代理密码"
    }
  ];

  return config;
}
```

两种写法的区别：

| 写法 | 适合场景 | 会出现在哪里 |
|---|---|---|
| `config._homeProxy` | 生成家宽真直连及可选链式路径 | `🏠 家宽IP`，可在 AI Agent、节点选择和 GLOBAL 里选择 |
| `config._customProxies` | 把它当普通备用出口使用 | `节点选择`、功能组 |
| `config._customProxies` + `dedicated: true` | 只允许指定用途使用 | 自定义规则组、国内出口或前置的明确授权 |

## 如何验证出口是否正确

打开 Clash Party 左侧「网络信息」，右上角可以切换检测源；面板未提供的站点可在浏览器打开。当前脚本统一维护七个检测站，分别观察四种出口：

| 检测源 | 用来判断什么 | 规则目标 | 预期结果 |
|---|---|---|---|
| `ipip.net` | 本机直连出口 | `DIRECT` | 显示本机直连公网 IP |
| `IP.SB` / `ip.sb` | 前置链路 | `🔗 前置`（无该组时退回前置代理节点或 `DIRECT`） | 显示 `🔗 前置` 当前选中节点的出口；选 `DIRECT` 时即本机直连 |
| `ipwho.is` | 普通代理出口 | `节点选择` | 显示该组当前选择链路的最终出口 |
| `ipapi.is` | AI 专用出口 | `🤖 AI Agent` | 显示 AI Agent 当前选择的出口；如果选了 `🏠 家宽IP`，就显示家宽 IP |
| `ip.net.coffee` | AI 出口诊断 | `🤖 AI Agent` | 辅助观察 AI 出口、DNS 与协议表现 |
| `ping0.cc`、`ipinfo.io` | AI 出口辅助检测 | `🤖 AI Agent` | 与 ipapi.is 核对 AI 最终出口 |

简单判定方式：

```text
ipapi.is → 看 AI 相关流量最终走哪里
ipwho.is → 看节点选择的默认代理出口
ip.sb    → 本机到订阅节点前的第一跳（🔗 前置）；前置为 DIRECT 时就是直连公网 IP
ipip.net → 本机直连公网 IP（不经前置）
```

如果你要验证美国静态家庭 IP：

1. Clash Party 保持规则模式
2. 确认请求通过 TUN、系统代理或应用显式代理进入 Mihomo
3. `出口IP凭证.js` 排在 `完全覆写.js` 前面
4. 在 `🤖 AI Agent` 里选择 `🏠 家宽IP`
5. 打开「网络信息」，选择 `ipapi.is` 并刷新
6. 对照你预期的固定出口 IP，并在连接详情确认命中 AI Agent 和家宽链路；国家/地区只能辅助判断

如果你要验证前置代理：

1. 重新应用配置，确认 `🔗 前置` 已列出需要的节点
2. 在 `🔗 前置` 手动选择该节点（普通节点显示为 `⤴ 原名`）
3. 打开 `ip.sb`，查看 `🔗 前置` 当前选中节点的出口
4. 期望看到一级代理/国内云服务器的公网 IP

规则模式下，`ipip.net` 显示本机直连出口，不能用来验证前置。`IP.SB` 用于验证前置，`ipwho.is` 用于验证节点选择的最终出口。`🔗 前置` 选为 DIRECT 时，前置检测显示的也是本机直连出口。全局模式不使用这些分流规则，而是跟随 GLOBAL。

如果浏览器与 Clash Party 面板检测结果不一致，检查连接的 TCP/UDP 类型。脚本优先拒绝非直连检测站及子域名的 UDP/443，让支持回退的客户端改用 TCP，避免不支持 UDP 的出口被内核跳过后误用直连；不会修改节点的 `udp` 声明或其他网站的 UDP。更新后重新应用覆写，关闭连接列表中该站的旧连接，再刷新检测页面和面板。预期 QUIC 请求显示 REJECT，新的 TCP 请求显示对应检测策略及所选节点；不要把正常的 QUIC 拒绝记录当成代理故障。若客户端没有自动回退，应改用 TCP 检测，不能仅凭规则存在认定修复已生效。

### 检测站如何统一维护

只修改 [完全覆写.js](../src/完全覆写.js) 顶部的 `NETWORK_PROBES`，不再分别修改 AI 域名、DNS、Sniffer 或规则构造函数：

```javascript
{ domain: "ip.sb", target: "front", purpose: "前置组当前出口", rejectQuic: true }
```

| 字段 | 含义 |
|---|---|
| `domain` | 小写域名，不含协议、路径或端口；统一后缀匹配，覆盖根域名和子域名 |
| `target` | `direct` 本机直连；`front` 前置；`node` 节点选择；`ai` AI Agent |
| `purpose` | 说明该站观察什么，避免把前置 IP 当作业务最终出口 |
| `rejectQuic` | 是否拒绝该站 UDP/443；代理检测默认 true，独立于 `rejectAiQuic` |

清单自动生成连续的检测规则区段，优先于普通业务分类和浏览器/AI 进程规则；仍保留更高优先级的代理服务器防回环、Tailscale 与 WebRTC 特殊规则。相同条件的自定义业务规则不能覆盖检测规则。未知用途、重复域名或父子域名重叠会报错，防止清单相互遮挡。

DNS 与嗅探同样从清单派生：直连检测使用本地直连 DNS，前置与节点检测的 DoH 分别经对应出口；AI 检测沿用 `overseasDnsTarget`（默认 AI Agent）。检测页展示的递归 DNS 地址不等于出口 IP，浏览器自定义安全 DNS 也可能绕过这些 DNS 设置。删除清单条目会一并删除该条目派生的规则，而不是留下旧的 AI 补充域名。

修改后运行 `npm test` 和 `node scripts/sync-community-rules.js --check`，并同步本节用途表。之后重新应用客户端覆写、建立新连接，核对实际链路；清单验证的是规则模式，全局模式仍由 GLOBAL 决定。

### 单独测试出口节点

如果要排查某个出口节点本身是否稳定，可以绕过 Clash 分流，直接用仓库脚本批量测试。这个方法适合测试 `家宽IP`、公司代理、自定义出口这类 HTTP/HTTPS 出口节点：

```bash
python3 scripts/proxy-reliability-test.py \
  --scheme http \
  --host 你的出口IP或域名 \
  --port 代理端口 \
  --username 用户名 \
  --password 密码 \
  --url https://ipapi.is/ \
  --count 50 \
  --concurrency 2 \
  --tcp-check \
  --csv /tmp/proxy-reliability.csv
```

如果你已经有完整代理地址，也可以直接写：

```bash
python3 scripts/proxy-reliability-test.py \
  --proxy http://user:pass@192.168.88.10:3128 \
  --url https://ipwho.is/ \
  --count 30 \
  --timeout 10 \
  --json
```

脚本输出里的 `success_rate` 按 HTTP 可达性统计，`p90` 和 `max` 可以看抖动。目标 4xx（例如 404）仍算可达，不代表业务成功；407 表示代理认证失败，5xx、连接/隧道错误均计为失败。工具只支持 HTTP/HTTPS 代理，不支持 SOCKS5。Clash 分流是否真的命中，仍然以「网络信息」和连接图为准。

## 与 Tailscale 共存

脚本默认按标准 Tailscale 方式共存。远程设备把本机作为 Exit Node 时，默认不提前截获这类转发流量，而是继续走完整分流规则：AI 域名走 `🤖 AI Agent`，GitHub 走 `🐙 GitHub`，国内走 `🇨🇳 国内`，最后进入 `🐟 兜底`。

脚本会让 Tailnet 目的地址和 MagicDNS 最终保持直连：

```text
100.64.0.0/10 → 🧩 Tailnet 内部直连 → DIRECT
100.100.100.100/32 → 🧩 Tailnet 内部直连 → DIRECT
fd7a:115c:a1e0::/48 → 🧩 Tailnet 内部直连 → DIRECT
*.ts.net → 🧩 Tailnet 内部直连 → DIRECT
```

`*.ts.net` 排除 Mihomo Fake-IP；脚本不为它添加显式上游 DNS 策略或 hosts，也不会开启或配置系统 MagicDNS。是否使用 Tailscale 解析仍取决于系统 DNS 和应用设置，不能仅凭规则存在保证解析成功。

顶部默认 `routeExcludeCidrs` 只含 `100.64.0.0/10`、`100.100.100.100/32`；`excludeProxyServerFromTun` 另将私网/Tailnet IPv4 字面代理地址以 `/32` 排除。Tailnet IPv6 的 DIRECT 规则不等于 TUN 已排除该前缀，`subnetCidrs` 也不会自动扩大 TUN 排除范围；需要时显式添加 `routeExcludeCidrs`。显式 HTTP/SOCKS 代理请求已进入内核，仍需靠分流规则处理。

Tailscale 控制面域名和 App 进程默认也是 `DIRECT`。以下为常用项摘录，修改顶部对应字段，不要用摘录覆盖整个对象：

```javascript
tailscale: {
  enable: true,
  monitorGroups: true,
  hideMonitorGroups: true,
  subnetCidrs: [],
  controlPlaneTarget: "DIRECT",
  processTarget: "DIRECT",
  forceExitNodeTraffic: false,
  forceExitNodeTrafficTarget: "节点选择"
}
```

默认额外生成三个监控组，方便在连接信息里区分 Tailscale 流量；它们带 `hidden: true`，减少日常列表干扰。测速地址随 location 或 `urlTestProbeUrl` 变化，测速成功不代表整个 Tailnet 都可达。

| 监控组 | 默认成员 | 说明 |
|---|---|---|
| `🧩 Tailnet 内部直连` | `DIRECT` | Tailnet 目的地址，例如 `100.64.0.0/10` 和 `*.ts.net` |
| `🧩 Tailscale 控制面` | `DIRECT` | `tailscale.com`、`tailscale.io` |
| `🧩 Tailscale 进程` | `DIRECT` | Tailscale App / 服务进程 |

如果本机访问 `tailscale.com` 官方域名也受污染，可以先把 `controlPlaneTarget` 改成前置代理名称或 `节点选择`。`monitorGroups` 设为 `false` 时，不再创建这些中间监控组，规则会直接指向配置目标。`hideMonitorGroups` 默认是 `true`；临时排查时可改成 `false`，让监控组出现在代理组列表里。`processTarget` 涉及 Tailscale 进程本身，除非你明确知道要这么做，否则建议保持 `DIRECT`。

如果你在 Tailscale 里启用了 subnet route，例如公司内网 `192.168.88.0/24`，并希望 Clash Party 连接图里明确显示这些目标走的是 Tailnet，可以这样填：

```javascript
tailscale: {
  enable: true,
  monitorGroups: true,
  hideMonitorGroups: true,
  subnetCidrs: ["192.168.88.0/24"]
}
```

命中这些网段的连接会进入 `🧩 Tailnet 内部直连`，组内默认是 `DIRECT`。

只有想让通过本机 Exit Node、匹配 Tailnet 来源规则的公网访问一刀切走某个出口时，才开启 `forceExitNodeTraffic`。本地目的地仍先保护，其余请求的强制出口优先于 AI、功能组和检测站规则；默认关闭时才沿用正常业务分流。

## 常见问题

### 不配置家宽 IP 能用吗？

可以。只导入 `完全覆写.js` 时，脚本会进入纯分流模式，不会创建家宽节点，但 `🤖 AI Agent` 仍然会出现。你可以在里面选择地区组、自定义出口、订阅裸节点或 DIRECT。

### 为什么我没有看到 `🏠 家宽IP`？

通常是因为没有正确导入 `出口IP凭证.js`，或者导入顺序错了。确认顺序是：

```text
出口IP凭证.js
完全覆写.js
```

使用前置时顺序不变，不需要额外导入前置脚本。

### 为什么 `🤖 AI Agent` 里没有自动选择？

这是直接候选的设计，不是固定出口保证。`节点选择`、地区组和家宽跳板仍可能自动选节点；如需固定最终 IP，应在 AI Agent 中明确选择固定节点或家宽组，并检查最终链路。

### 台湾为什么显示 `🇨🇳|台湾`？

脚本会使用中国旗标显示台湾地区组，避免在代理组里出现不符合预期的图标。分组名称仍然保留 `台湾`，方便识别节点地区。

### 我的自动选择组不叫「自动选择」怎么办？

打开 `完全覆写.js`，修改：

```javascript
autoSelectGroupName: "自动选择"
```

把 `自动选择` 改成你订阅里真实的自动测速组名称。

### 浏览器要不要强制走 AI Agent？

默认不要。浏览器流量很复杂，全部强制到 AI Agent 可能影响普通网页体验。只有你明确需要浏览器也使用 AI Agent 时，再把下面这个参数改成 `true`：

```javascript
enableChainRegionBrowserProcessProxy: true
```

### AI 工具包括哪些？

脚本覆盖了常见 AI 应用和命令行工具，例如 Claude、Claude Code、ChatGPT、Perplexity、Cursor、Antigravity、Gemini CLI、Codex CLI 等。macOS 和 Windows 的常见进程名都已覆盖。

## 新手推荐的最终方案

第一次使用，建议按这个顺序来：

1. 先只导入 `完全覆写.js`，确认分流正常
2. 如果本机到订阅节点经常全红，在 `🔗 前置` 选择本机可直连的节点；新增节点仍填在 `出口IP凭证.js`
3. 如果确实需要 AI 工具走美国静态家庭 IP，再添加 `出口IP凭证.js`
4. 最后再考虑自定义出口和浏览器强制 AI Agent

核心记忆点：只维护 `出口IP凭证.js`（可选）和 `完全覆写.js`（必选）；有凭证配置时，将它放在主脚本前面。
