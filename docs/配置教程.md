# Clash 完全覆写脚本低门槛配置教程

这篇教程面向第一次使用 Clash Party / Mihomo Party 覆写的人。你不需要理解脚本源码，只要按自己的情况导入文件，并修改少量配置项即可。

> 当前文档由飞书教程内容整理而来，并按仓库当前脚本功能同步更新。飞书里的截图和 callout 已转换为 GitHub Markdown，避免图片 token 或飞书专有标签在 GitHub 上渲染失败。

## 这个脚本解决什么问题

这个项目会在你的订阅配置上自动补齐代理组、分流规则和 DNS 配置。最低门槛用法是只导入 `完全覆写.js`，不配置家宽 IP、不配置自定义出口，也可以获得功能组、域名规则、国内直连和兜底节点选择。

| 场景 | 脚本会怎么处理 |
|---|---|
| YouTube、Netflix、Twitter、Spotify 等 | 走 `🌍 国际媒体` 组 |
| Telegram、Discord | 走 `📲 Telegram` 组 |
| GitHub、GitHub Copilot | 走 `🐙 GitHub` 组 |
| Microsoft、Office、Bing、Xbox、VS Code | 走 `Ⓜ️ 微软服务` 组，默认直连 |
| Steam、Epic、Nintendo、PlayStation | 走 `🎮 游戏平台` 组 |
| Apple、iCloud、App Store | 走 `🍎 Apple` 组 |
| 国内网站和国内 IP | 自动直连 |
| Claude、ChatGPT、Cursor、Codex 等 AI 工具 | 走独立的 `🤖 AI Agent` 组 |
| AI 网站的 HTTP/3 / QUIC | 默认拒绝 UDP/443 并立即回退 HTTPS/TCP，避免不支持 UDP 的代理出口发生直连泄漏 |
| 浏览器 WebRTC | 默认拒绝常用 STUN UDP 端口，避免 HTTP 代理出口下暴露本地公网 IP |

## 先选你的使用模式

| 你想实现什么 | 需要导入哪些文件 | 适合谁 |
|---|---|---|
| 只想自动分流，不折腾家宽 IP | 只导入 `完全覆写.js` | 新手、普通代理订阅用户 |
| 想解决本机网络到订阅节点污染或超时 | 先导入 `前置代理.js`，再导入 `完全覆写.js` | 有一级代理或国内云服务器代理的人 |
| 想让 AI 工具走美国静态家庭 IP | 先导入 `出口IP凭证.js`，再导入 `完全覆写.js` | 有静态家庭 IP 或家宽代理的人 |
| 想额外加入自己的 HTTP/SOCKS5 出口节点 | 先导入 `出口IP凭证.js`，再导入 `完全覆写.js` | 有备用出口、自建代理的人 |
| 没有订阅，只想使用公司节点/固定 IP | 导入 `无订阅基础配置.yaml`，再导入 `出口IP凭证.js` 和 `完全覆写.js` | dedicated 公司代理、静态 IP 用户 |

如果同时使用前置代理和出口凭证，推荐顺序是：

```text
1. 前置代理.js
2. 出口IP凭证.js
3. 完全覆写.js
```

顺序不能反。前两个脚本负责把配置塞进 `config`，主脚本 `完全覆写.js` 再读取它们并生成代理组和规则。

## 方式一：纯分流模式

适合只想让订阅配置更好用的人：自动分组、自动分流、国内直连。

1. 打开仓库里的 `src/完全覆写.js`
2. 下载到本地
3. 在 Clash Party / Mihomo Party 的「覆写」列表里新增 JavaScript 覆写
4. 选择或粘贴 `完全覆写.js`
5. 启用覆写，回到订阅配置重新应用

导入成功后，代理组里会出现类似这些分组：

```text
自动选择
节点选择

🌍 国际媒体
📲 Telegram
🐙 GitHub
Ⓜ️ 微软服务
🎮 游戏平台
🍎 Apple

🤖 AI Agent
🇭🇰|香港
🇺🇸|美国
🇯🇵|日本
🇨🇳|台湾
```

如果你只需要普通分流，到这里就完成了。

## 方式二：无订阅模式

适合没有机场订阅，只想使用 dedicated 公司代理、自建 HTTP/SOCKS5 节点或固定 IP 的人。

1. 导入 [`src/无订阅基础配置.yaml`](../src/无订阅基础配置.yaml) 作为基础配置
2. 复制 [`src/出口IP凭证_样本.js`](../src/出口IP凭证_样本.js)
3. 重命名为 `出口IP凭证.js`
4. 在 `出口IP凭证.js` 里填入 `config._customProxies` 或 `config._homeProxy`
5. 覆写顺序设置为：`出口IP凭证.js` → `完全覆写.js`

无订阅模式不会生成地区组，也不会强行创建 `自动选择`。如果空 YAML 里没有订阅节点，也没有配置自定义节点或固定 IP，脚本会直接报错，避免生成一个看起来可用但实际没有出口的配置。

导入成功后，常见代理组会更简单：

```text
节点选择
GLOBAL
🌍 国际媒体
📲 Telegram
🐙 GitHub
Ⓜ️ 微软服务
🎮 游戏平台
🍎 Apple
🎯 直连
🤖 AI Agent
🏠 家宽IP（配置固定 IP 时）
```

## 方式三：配置前置代理

前置代理适合本机所在网络到订阅节点 DNS 污染严重、晚高峰 URLTest 大面积超时，或者希望先从一级代理/国内云服务器出站，再连接订阅里的外部节点。

1. 复制 [`src/前置代理_样本.js`](../src/前置代理_样本.js)
2. 重命名为 `前置代理.js`
3. 取消注释 `config._frontProxy`
4. 填入你的前置代理地址和端口

在有订阅模式下，前置代理会自动绑定到订阅原始节点。`出口IP凭证.js` 里的自定义节点默认不走前置代理；如果你希望某一个自定义节点也先走前置代理，在这个节点上加：

```javascript
useFrontProxy: true
```

前置代理不是最终出口，不会进入 `节点选择` 或 `🤖 AI Agent`。它主要用于改善本机到上游节点的第一跳连接，检测时看 `IP.SB` / `ip.sb`。

示例：

```javascript
function main(config) {
  config._frontProxy = {
    name: "一级前置代理",
    type: "socks5",
    server: "你的一级代理服务器IP",
    port: 1080
  };

  return config;
}
```

配置后，订阅原始节点会先走这个前置代理；URLTest 测速地区节点时也会先走前置代理。自定义出口、家宽 IP 和 DIRECT 不会被前置代理覆盖。

> 前置代理不是订阅最终节点，不会出现在 `节点选择` 或 `🤖 AI Agent` 里。它会出现在 `GLOBAL` 里；如果希望全局所有流量都先走一级代理，请在 `GLOBAL` 中选择它。`DIRECT` 是 Clash 内置直连，选择 `GLOBAL → DIRECT` 时仍然会真实直连。

## 方式四：配置美国静态家庭 IP

适合你有一个自己的家宽 HTTP/SOCKS5 代理，或者通过静态住宅 IP 服务购买了固定美国出口，并希望 AI 工具流量走这个出口。

配置后，脚本会新增：

| 新增内容 | 作用 |
|---|---|
| `家宽IP` 节点 | 你的家宽 HTTP/SOCKS5 出口，真直连，不挂 `dialer-proxy` |
| `家宽IP链式` 节点 | 有订阅或自定义跳板时自动生成，先走 `🔗 家宽跳板` 再访问家宽出口 |
| `🔗 家宽跳板` 组 | 决定 `家宽IP链式` 前面走哪条订阅线路或自定义出口 |
| `🏠 家宽IP` 组 | 可被 `🤖 AI Agent` 选择的家庭 IP 出口 |

### 复制凭证样本

复制 [`src/出口IP凭证_样本.js`](../src/出口IP凭证_样本.js)，重命名为：

```text
出口IP凭证.js
```

### 填写家宽 IP 信息

打开 `出口IP凭证.js`，找到 `config._homeProxy`，取消注释并填入真实信息：

```javascript
function main(config) {
  config._homeProxy = {
    type: "socks5",
    server: "你的家宽IP或域名",
    port: 1080,
    username: "你的账号",
    password: "你的密码"
  };

  return config;
}
```

字段说明：

| 字段 | 怎么填 |
|---|---|
| `type` | `http` 或 `socks5` |
| `server` | 家宽代理的 IP 或域名 |
| `port` | 家宽代理端口，例如 `1080`、`7890` |
| `username` | 如果代理需要账号，再填写 |
| `password` | 如果代理需要密码，再填写 |

不要把填写了账号密码的 `出口IP凭证.js` 上传到公开仓库。这个文件应该只保存在你自己的电脑里。

## 方式五：添加自定义出口节点

如果你还有普通 HTTP/SOCKS5 出口，可以写到 `config._customProxies`。这些节点会被注入到代理节点里，并出现在 `节点选择` 和相关功能组中。只允许公司域名或内网网段使用的代理不要使用这种默认写法。

示例：

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "自定义出口",
      type: "http",
      server: "10.0.0.1",
      port: 3128,
      // 可选：如果这个出口在 Tailscale subnet 内，填 Tailscale 网卡名，例如 "utun4"
      interfaceName: ""
    }
  ];

  return config;
}
```

如果普通出口位于 Tailscale subnet 内，并且 Clash Party 虚拟网卡开启了「自动选择流量出口接口」，建议保留该全局开关，同时只在对应节点上配置 `interfaceName`。macOS 可执行 `route -n get 代理IP`，输出里的 `interface` 即为应填写的网卡名。

如果不想手动维护网卡名，可以使用仓库内的辅助脚本。先预览：

```bash
node scripts/update-interface-name.js \
  --file "/path/to/出口IP凭证.js" \
  --server 10.96.0.100
```

确认无误后写入：

```bash
node scripts/update-interface-name.js \
  --file "/path/to/出口IP凭证.js" \
  --server 10.96.0.100 \
  --write
```

如果自定义出口也需要账号密码，继续追加：

```javascript
{
  name: "带认证的出口",
  type: "http",
  server: "example.com",
  port: 3128,
  username: "你的账号",
  password: "你的密码"
}
```

### 自定义规则组

如果某些固定域名或网段需要走一个单独目标，但这个目标不应该作为普通出口出现在 `节点选择` 里，可以使用 `config._customRuleGroups`。这类配置适合“指定规则 → 指定策略组”的场景。

复制 `src/自定义规则组_样本.js`，按需改名后导入到 `完全覆写.js` 之前：

```javascript
function main(config) {
  config._customRuleGroups = [
    {
      name: "自定义业务",
      proxy: {
        name: "自定义业务节点",
        type: "socks5",
        server: "127.0.0.1",
        port: 10880
      },
      rules: [
        "DOMAIN,service.example.test",
        "DOMAIN-SUFFIX,internal.example.test"
      ],
      testUrl: "http://connect.rom.miui.com/generate_204"
    }
  ];

  return config;
}
```

脚本会生成 `自定义业务` 策略组，并把上面的规则指向该组。自定义规则组的测速地址按“分组 `testUrl` → 全局 `USER_OPTIONS.urlTestProbeUrl` → 脚本内置默认值”的顺序取值。`proxy` 是可选的；如果目标节点已经存在，也可以写：

```javascript
proxies: ["已有节点名"]
```

或者在特定机器上直接走系统网络：

```javascript
proxies: ["DIRECT"]
```

`_customRuleGroups` 也支持无订阅模式。只导入空 YAML、自定义规则组文件和 `完全覆写.js` 时，脚本仍会生成基础分流结构。

### 公司内网专用代理

公司代理不应作为普通公网出口进入 `节点选择`。把它标记为 `scope: "dedicated"`，再由自定义规则组显式引用：

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "公司代理",
      scope: "dedicated",
      type: "http",
      server: "10.0.0.2",
      port: 3128,
      // 公司代理位于 Tailscale subnet 时填写，例如 "utun4" 或 "tailscale0"
      interfaceName: ""
    }
  ];

  config._customRuleGroups = [
    {
      name: "公司内网",
      proxies: ["公司代理"],
      rules: [
        "DOMAIN-SUFFIX,example.corp",
        { type: "IP-CIDR", value: "10.0.0.0/8", option: "no-resolve" }
      ]
    }
  ];

  return config;
}
```

dedicated 节点只会出现在明确引用它的规则组中，不会进入 `节点选择`、AI、媒体、GitHub、游戏平台、家宽跳板或 `GLOBAL`。如果没有被 `_customRuleGroups.proxies` 引用，脚本会拒绝生成配置，避免专用代理成为不可见的错误出口。

## AI Agent 组怎么理解

`🤖 AI Agent` 是 AI 域名和 AI 进程的独立策略组。它不会直接放入总的 `自动选择` 组，因为 AI 出口通常需要更明确、更稳定。

Gemini、AI Studio、Antigravity、Generative Language API 等明确的 Google AI 域名走 `🤖 AI Agent`。通用 Google 服务，例如 `google.com`、`googleapis.com`、Gmail 和 Google Cloud，走 `节点选择`。YouTube 的 `youtubei.googleapis.com`、`youtube.googleapis.com` 和 `yt3.ggpht.com` 虽位于共享 Google 域名下，仍会优先走 `🌍 国际媒体`。

有家宽 IP 时：

```text
🏠 家宽IP / 节点选择 / 地区组 / 普通自定义出口 / DIRECT
```

无家宽 IP 时：

```text
节点选择 / 地区组 / 普通自定义出口 / 订阅裸节点 / DIRECT
```

这里的关键点是：

- 有家宽 IP 时，AI Agent 里不展开订阅裸节点，避免高阶场景下列表过长
- 无家宽 IP 时，保留订阅裸节点，方便单独给 AI 选择某个支持 AI 的节点
- 地区组会保留，例如 `🇺🇸|美国`、`🇭🇰|香港`、`🇨🇳|台湾`
- 总的 `自动选择` 不放进 AI Agent，避免 AI 出口选择过于含糊

## 常用参数怎么改

`完全覆写.js` 顶部有一段 `USER_OPTIONS`：

```javascript
var USER_OPTIONS = {
  autoSelectGroupName: "自动选择",
  urlTestProbeUrl: "http://connect.rom.miui.com/generate_204",
  proxyProbeUrl: "https://www.gstatic.com/generate_204",
  overseasDnsTarget: "🤖 AI Agent",
  directProxyServerRules: true,
  proxyServerResolvedIps: {},
  rejectAiQuic: true,
  rejectWebRtcUdp: true,
  enableChainRegionBrowserProcessProxy: false,
  enableChainRegionAiCliProcessProxy: true
};
```

一般只需要理解这几个：

| 参数 | 默认值 | 什么时候要改 |
|---|---:|---|
| `autoSelectGroupName` | `自动选择` | 如果你的订阅自动测速组不叫「自动选择」，就改成你的组名 |
| `urlTestProbeUrl` | `http://connect.rom.miui.com/generate_204` | 直连、Tailscale 监控和自定义业务组的界面健康检查地址 |
| `proxyProbeUrl` | `https://www.gstatic.com/generate_204` | 自动选择、地区组、节点选择、AI Agent 和家宽跳板等代理出海组的测速地址 |
| `overseasDnsTarget` | `🤖 AI Agent` | 海外及未知域名的 DoH 连接出口；默认随 AI Agent 的家宽或指定节点出站，需要普通出海时改为 `节点选择` |
| `directProxyServerRules` | `true` | 将代理节点服务器地址生成 `DIRECT` 规则，避免局域网中下游 Clash 再次代理节点连接 |
| `proxyServerResolvedIps` | `{}` | 当代理服务器写的是域名、而下游 Clash 只看到解析后的 IP 时，填写域名对应的 IP 列表，额外生成 `/32` 或 `/128 DIRECT` 规则 |
| `rejectAiQuic` | `true` | 拒绝 AI 域名 UDP/443，避免 HTTP 家宽出口不支持 UDP 时继续匹配到直连；整条链路支持 UDP 后才关闭 |
| `rejectWebRtcUdp` | `true` | 拒绝常用 STUN UDP 端口 `3478`、`5349`、`19302`，防止 WebRTC 暴露本地公网 IP；需要实时音视频且整条链路支持 UDP 时才关闭 |
| `enableChainRegionBrowserProcessProxy` | `false` | 想让 Chrome、Edge、Dia、Atlas 等浏览器也走 AI Agent 时改为 `true` |
| `enableChainRegionAiCliProcessProxy` | `true` | 想让 Claude Code、Gemini CLI、Codex CLI 等 AI 命令行工具走 AI Agent，保持 `true` |

如果不知道要不要改，就先保持默认。默认配置更稳：AI 工具走独立组，浏览器不强制走 AI Agent。

例如代理服务器是 `edge.example.com`，而局域网下游的 Clash 已经只看到它解析后的地址时，可以这样填写：

```javascript
proxyServerResolvedIps: {
  "edge.example.com": ["203.0.113.10", "2001:db8::10"]
}
```

当这个域名的 IP 发生变化时，需要同步更新列表。Tailscale 自身的 STUN 流量已优先于浏览器 WebRTC 防泄漏规则处理，不需要在这里填写。

DNS 检测页显示的是递归 DNS 服务商的地址，例如 Google、Cloudflare 或 Quad9，不会等于家宽出口 IP。默认配置保证这些 DoH 请求经 AI Agent 发起；如果检测结果仍显示中国大陆 DNS，优先检查浏览器是否单独启用了安全 DNS，而不是只修改覆写脚本。

| Password | `password` |

不要把这四项直接填到 `完全覆写.js` 里。正确做法是单独复制一份 `出口IP凭证.js`，把美国静态 IP 当成 `config._homeProxy` 配进去。

### 先用命令测试代理是否可用

如果电脑上可以使用命令行，建议先测试一次，避免直接填进 Clash 后不好排查。

SOCKS5 示例：

```bash
curl --proxy socks5://username:password@Host:Port https://mayips.com
```

HTTP 示例：

```bash
curl --proxy http://username:password@Host:Port https://mayips.com
```

把 `username`、`password`、`Host`、`Port` 换成 Cliproxy 使用列表里的真实信息。如果返回的 IP 信息显示为美国，说明这个静态家庭 IP 可以正常使用。

## 如何配置美国 IP 节点

这一段是整个教程最关键的地方：申请到美国静态 IP 以后，要把它配置成家宽 IP 出口节点，而不是普通订阅节点。

### 第 1 步：创建 `出口IP凭证.js`

从仓库复制这个文件：

```text
src/出口IP凭证_样本.js
```

重命名为：

```text
出口IP凭证.js
```

这个文件只放在你本地电脑里，用来保存美国 IP 的 Host、Port、Username、Password。不要把填好密码的版本提交到 GitHub。

### 第 2 步：判断代理类型

Cliproxy 或其他静态 IP 服务一般会给你 HTTP 或 SOCKS5 两种类型之一。你只需要看后台给出的连接方式：

| 后台给出的类型 | `type` 应该填写 |
|---|---|
| SOCKS5 / Socks5 | `socks5` |
| HTTP / HTTPS | `http` |

如果后台同时提供 HTTP 和 SOCKS5，新手优先选 SOCKS5；如果你的服务只给 HTTP，就按 HTTP 配。

### 第 3 步：把美国 IP 填到 `config._homeProxy`

如果 Cliproxy 给的是 SOCKS5，就这样填：

```javascript
function main(config) {
  config._homeProxy = {
    type: "socks5",
    server: "Cliproxy 给你的 Host",
    port: 12345,
    username: "Cliproxy 给你的 Username",
    password: "Cliproxy 给你的 Password"
  };

  return config;
}
```

如果 Cliproxy 给的是 HTTP 代理，就这样填：

```javascript
function main(config) {
  config._homeProxy = {
    type: "http",
    server: "Cliproxy 给你的 Host",
    port: 12345,
    username: "Cliproxy 给你的 Username",
    password: "Cliproxy 给你的 Password"
  };

  return config;
}
```

注意：

- `server` 填 Host / Server，不要加 `http://` 或 `socks5://`
- `port` 是数字，不要加引号
- `username` 和 `password` 必须保留引号
- `type` 只能是 `http` 或 `socks5`

### 第 4 步：按顺序导入覆写

在 Clash Party / Mihomo Party 的「覆写」页面里，按下面顺序启用：

```text
1. 出口IP凭证.js
2. 完全覆写.js
```

如果你还配置了前置代理，顺序是：

```text
1. 前置代理.js
2. 出口IP凭证.js
3. 完全覆写.js
```

导入后重新应用订阅配置。配置成功时，代理组里应该能看到：

```text
🔗 家宽跳板
🏠 家宽IP
🤖 AI Agent
```

### 第 5 步：在 AI Agent 里选择美国 IP

打开「代理组与节点」，找到：

```text
🤖 AI Agent
```

如果你已经配置了美国静态 IP，`🤖 AI Agent` 里应该可以选择：

```text
🏠 家宽IP
```

选择 `🏠 家宽IP` 后，Claude、ChatGPT、Cursor、Codex、Gemini CLI 等 AI 工具会优先走这个美国静态 IP。

### 可选：把美国 IP 当普通自定义节点

大多数情况下，美国静态 IP 应该配置为 `config._homeProxy`。只有你想让它像普通节点一样出现在 `节点选择` 或其他功能组里时，才把它写到 `config._customProxies`：

```javascript
function main(config) {
  config._customProxies = [
    {
      name: "美国静态IP",
      type: "socks5",
      server: "Cliproxy 给你的 Host",
      port: 12345,
      username: "Cliproxy 给你的 Username",
      password: "Cliproxy 给你的 Password"
    }
  ];

  return config;
}
```

两种写法的区别：

| 写法 | 适合场景 | 会出现在哪里 |
|---|---|---|
| `config._homeProxy` | AI 工具固定走美国静态家庭 IP | `🏠 家宽IP`，并可在 `🤖 AI Agent` 里选择 |
| `config._customProxies` | 把它当普通备用出口使用 | `节点选择`、功能组 |
| `config._customProxies` + `scope: "dedicated"` | 只允许指定业务使用 | 仅 `_customRuleGroups` 显式引用的规则组 |

## 如何验证出口是否正确

打开 Clash Party 左侧「网络信息」，右上角可以切换检测源。当前脚本会显式分流三个检测源：

| 检测源 | 用来判断什么 | 规则目标 | 预期结果 |
|---|---|---|---|
| `ipapi.is` | AI 专用出口 | `🤖 AI Agent` | 显示 AI Agent 当前选择的出口；如果选了 `🏠 家宽IP`，就显示家宽 IP |
| `ipwho.is` | 普通代理出口 | `节点选择` | 显示默认代理出口，不受 AI Agent 和公司内网代理影响 |
| `IP.SB` / `ip.sb` | 前置链路或直连出口 | 有前置代理时指向前置代理；无前置代理时 `DIRECT` | 开启前置代理时显示一级代理 IP；未开启时显示本机直连公网 IP |

简单判定方式：

```text
ipapi.is → 看 AI 相关流量最终走哪里
ipwho.is → 看节点选择的默认代理出口
ip.sb    → 看本机到订阅节点前的第一跳；没前置代理时就是直连公网 IP
```

如果你要验证美国静态家庭 IP：

1. Clash Party 保持规则模式
2. TUN / 虚拟网卡保持开启
3. `出口IP凭证.js` 排在 `完全覆写.js` 前面
4. 在 `🤖 AI Agent` 里选择 `🏠 家宽IP`
5. 打开「网络信息」，选择 `ipapi.is` 并刷新
6. 重点看国家/地区是否为 United States / 美国

如果你要验证前置代理：

1. `前置代理.js` 排在 `完全覆写.js` 前面
2. 重新应用订阅配置
3. 打开「网络信息」，选择 `IP.SB` 并刷新
4. 期望看到一级代理/国内云服务器的公网 IP

如果配置了 `前置代理.js`，地区组和 URLTest 测速订阅节点时会先走前置代理，因此 `IP.SB` 应显示前置代理 IP；但 `ipwho.is` 仍应显示普通代理节点的最终出口 IP。

如果要排查某个出口节点本身是否稳定，可以绕过 Clash 分流，直接用仓库脚本批量测试。这个方法适合测试 `家宽IP`、公司代理、自定义出口这类 HTTP/HTTPS 出口节点：

```bash
python3 scripts/proxy-reliability-test.py \
  --scheme http \
  --host 你的出口IP或域名 \
  --port 代理端口 \
  --username 用户名 \
  --password 密码 \
  --url https://ipapi.is/ \
  --count 50 \
  --concurrency 2 \
  --tcp-check \
  --csv /tmp/proxy-reliability.csv
```

如果你已经有完整代理地址，也可以直接写：

```bash
python3 scripts/proxy-reliability-test.py \
  --proxy http://user:pass@10.96.0.100:3456 \
  --url https://ipwho.is/ \
  --count 30 \
  --timeout 10 \
  --json
```

脚本输出里的 `success_rate` 可以判断稳定性，`p90` 和 `max` 可以看抖动。它测的是出口节点本身；Clash 分流是否真的命中，仍然以「网络信息」和连接图为准。

## 与 Tailscale 共存

脚本默认按标准 Tailscale 方式共存。远程设备把本机作为 Exit Node 时，默认不提前截获这类转发流量，而是继续走完整分流规则：AI 域名走 `🤖 AI Agent`，GitHub 走 `🐙 GitHub`，国内走直连，最后兜底到 `节点选择`。

脚本会让 Tailnet 目的地址最终保持直连：

```text
100.64.0.0/10 → 🧩 Tailnet 内部直连 → DIRECT
100.100.100.100/32 → 🧩 Tailnet 内部直连 → DIRECT
fd7a:115c:a1e0::/48 → 🧩 Tailnet 内部直连 → DIRECT
```

这样做是为了避免 Tailscale 的 WireGuard / DERP / MagicDNS 流量被 Clash 再代理一层，导致套娃或断联。

Tailscale 官方域名和 App 进程默认也是 `DIRECT`，但可以在 `完全覆写.js` 顶部调整：

```javascript
tailscale: {
  enable: true,
  monitorGroups: true,
  hideMonitorGroups: true,
  subnetCidrs: [],
  controlPlaneTarget: "DIRECT",
  processTarget: "DIRECT",
  forceExitNodeTraffic: false,
  forceExitNodeTrafficTarget: "节点选择"
}
```

默认会额外生成三个监控组，方便在 Clash Party 连接信息里看清 Tailscale 相关流量；这些组默认带 `hidden: true`，不在代理组列表里展示，避免 DIRECT 测速超时造成误解。

| 监控组 | 默认成员 | 说明 |
|---|---|---|
| `🧩 Tailnet 内部直连` | `DIRECT` | Tailnet 目的地址，例如 `100.64.0.0/10` 和 MagicDNS |
| `🧩 Tailscale 控制面` | `DIRECT` | `tailscale.com`、`tailscale.io`、`ts.net` |
| `🧩 Tailscale 进程` | `DIRECT` | Tailscale App / 服务进程 |

如果本机访问 `tailscale.com` 官方域名也受污染，可以先把 `controlPlaneTarget` 改成前置代理名称或 `节点选择`。`monitorGroups` 设为 `false` 时，不再创建这些中间监控组，规则会直接指向配置目标。`hideMonitorGroups` 默认是 `true`；临时排查时可改成 `false`，让监控组出现在代理组列表里。`processTarget` 涉及 Tailscale 进程本身，除非你明确知道要这么做，否则建议保持 `DIRECT`。

如果你在 Tailscale 里启用了 subnet route，例如公司内网 `192.168.88.0/24`，并希望 Clash Party 连接图里明确显示这些目标走的是 Tailnet，可以这样填：

```javascript
tailscale: {
  enable: true,
  monitorGroups: true,
  hideMonitorGroups: true,
  subnetCidrs: ["192.168.88.0/24"]
}
```

命中这些网段的连接会进入 `🧩 Tailnet 内部直连`，组内默认是 `DIRECT`。

只有想让远程设备通过本机 Exit Node 的公网访问全部一刀切走某个出口时，才把 `forceExitNodeTraffic` 改成 `true`。

## 常见问题

### 不配置家宽 IP 能用吗？

可以。只导入 `完全覆写.js` 时，脚本会进入纯分流模式，不会创建家宽节点，但 `🤖 AI Agent` 仍然会出现。你可以在里面选择地区组、自定义出口、订阅裸节点或 DIRECT。

### 为什么我没有看到 `🏠 家宽IP`？

通常是因为没有正确导入 `出口IP凭证.js`，或者导入顺序错了。确认顺序是：

```text
出口IP凭证.js
完全覆写.js
```

如果同时用了前置代理，则是：

```text
前置代理.js
出口IP凭证.js
完全覆写.js
```

### 为什么 `🤖 AI Agent` 里没有自动选择？

这是有意设计。AI 出口通常需要固定国家、固定节点或固定家宽 IP；总的 `自动选择` 可能随测速变化，容易导致 AI 账号或 API 出口不稳定。地区组仍然会保留。

### 台湾为什么显示 `🇨🇳|台湾`？

脚本会使用中国旗标显示台湾地区组，避免在代理组里出现不符合预期的图标。分组名称仍然保留 `台湾`，方便识别节点地区。

### 我的自动选择组不叫「自动选择」怎么办？

打开 `完全覆写.js`，修改：

```javascript
autoSelectGroupName: "自动选择"
```

把 `自动选择` 改成你订阅里真实的自动测速组名称。

### 浏览器要不要强制走 AI Agent？

默认不要。浏览器流量很复杂，全部强制到 AI Agent 可能影响普通网页体验。只有你明确需要浏览器也使用 AI Agent 时，再把下面这个参数改成 `true`：

```javascript
enableChainRegionBrowserProcessProxy: true
```

### AI 工具包括哪些？

脚本覆盖了常见 AI 应用和命令行工具，例如 Claude、Claude Code、ChatGPT、Perplexity、Cursor、Antigravity、Gemini CLI、Codex CLI 等。macOS 和 Windows 的常见进程名都已覆盖。

## 新手推荐的最终方案

第一次使用，建议按这个顺序来：

1. 先只导入 `完全覆写.js`，确认分流正常
2. 如果本机到订阅节点经常全红，再添加 `前置代理.js`
3. 如果确实需要 AI 工具走美国静态家庭 IP，再添加 `出口IP凭证.js`
4. 最后再考虑自定义出口和浏览器强制 AI Agent

核心记忆点：主脚本是 `完全覆写.js`；凭证脚本和前置代理脚本都是可选的；需要它们时，必须排在主脚本前面。
